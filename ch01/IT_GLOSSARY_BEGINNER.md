## 1. AI · 바이브코딩의 기본 원리

> *"코드를 직접 외우지 않아도 괜찮지만, AI가 어떻게 답을 만들어내는지 원리를 알면 훨씬 잘 지휘할 수 있습니다."*

- [🟡 지시] **바이브 코딩**(Vibe Coding): 개발자가 코드를 한 줄씩 직접 타이핑하는 대신, 자연어로 요구사항과 설계서(프롬프트)를 작성해 AI 에이전트에게 구현을 지시하고 결과물을 검증하는 설계자 중심의 개발 방식입니다.
- [🟢 원리] **에이전틱 엔지니어링**(Agentic Engineering): 단순한 코드 생성 요청을 넘어, AI 에이전트에게 명세(Spec)와 테스트 케이스를 제공하고 계획·구현·검증·배포의 전체 소프트웨어 엔지니어링 수명주기를 지휘하는 개발 패러다임입니다.
- [🟢 원리] **LLM**(Large Language Model, 대규모 언어 모델): 방대한 텍스트 데이터를 학습해 앞선 문맥을 바탕으로 뒤를 이을 확률이 높은 다음 단어(토큰)를 차례대로 예측하며 자연어와 코드를 생성하는 인공지능 모델입니다. (예: Gemini, Claude, GPT)
- [🟢 원리] **토큰**(Token): AI 모델이 텍스트를 읽고 계산하며 비용을 매기는 기본 단위(단어나 글자 조각)입니다.
- [🟢 원리] **토큰 이코노미**(Token Economy): AI 모델별 특성과 비용을 이해하고 토큰을 전략적으로 투입해 개발 생산성과 비즈니스 부가가치를 극대화하는 사고방식 및 운영 전략입니다.
- [🔴 생존] **비결정론적 생성**(Non-deterministic / 확률적 생성): 같은 질문을 입력해도 매번 확률 계산(주사위 굴리기)에 따라 조금씩 다른 구조나 디자인의 결과물이 나오는 LLM의 특성입니다.
- [🔴 생존] **할루시네이션**(Hallucination, 환각): AI가 사실이 아니거나 실제로 존재하지 않는 기능·라이브러리·정보를 확률적으로 그럴듯하게 지어내어 답변하는 현상입니다.
- [🔴 생존] **컨텍스트 윈도우**(Context Window): AI 모델이 한 번의 대화 세션 안에서 기억하고 동시에 처리할 수 있는 입력·출력 텍스트의 최대 용량입니다.
- [🟡 지시] **컨텍스트 격리**(Context Isolation): 메인 작업 세션의 대화 기록을 오염시키지 않기 위해, 탐색이나 리서치 작업을 별도의 깨끗한 세션(서브에이전트 등)으로 분리하는 전략입니다.
- [🔴 생존] **컨텍스트 오염/비대화**(Context Bloat / Context Window Pollution): 불필요한 에러 로그, 파일 전체 내용, 너무 길어진 대화 기록이 쌓여 AI의 집중력과 답변 품질이 떨어지는 현상입니다. (이럴 때는 새 대화창을 여는 것이 좋습니다.)

## 2. 프롬프트 · AI 에이전트 · 작업 환경

> *"AI를 똑똑한 작업 파트너로 부리기 위한 지시 방법과 도구의 이름들입니다."*

### 프롬프트와 지시 방법
- [🟡 지시] **프롬프트**(Prompt): AI 모델에게 작업을 지시하거나 질문을 던지는 자연어 입력문입니다.
- [🟡 지시] **프롬프트 엔지니어링**(Prompt Engineering): AI로부터 원하는 정확하고 일관된 결과를 얻기 위해 지시 문장의 구조, 제약 조건, 예시를 체계적으로 설계하는 기술입니다.
- [🟡 지시] **컨텍스트 엔지니어링**(Context Engineering): 말 한 줄(프롬프트)을 잘 쓰는 것을 넘어, 지금 AI의 기억 공간(컨텍스트 윈도우) 안에 어떤 규칙·문서·파일·대화 기록을 넣고 뺄지 전략적으로 구성하는 기술입니다.
- [🟡 지시] **시스템 프롬프트**(System Prompt): 대화 전반에 걸쳐 AI의 역할, 말투, 행동 규칙, 제약 조건을 최우선으로 고정하는 배경 지시문입니다.
- [🟡 지시] **규칙**(Rules): `.agents/rules/*.md` 등에 저장되어 매 대화 턴마다 컨텍스트에 상시 자동 포함되는 프로젝트의 고정 원칙과 금지 사항입니다.
- [🔴 생존] `AGENTS.md`: 프로젝트 루트에 위치하여 AI 에이전트(Antigravity 등)가 프로젝트 전반에서 준수해야 할 전역 행동 지침, 보안 제약, 아키텍처 규칙을 선언하는 표준 문서입니다.
- [🔴 생존] **네거티브 제약**(Negative Constraints): "코드 생략 금지", "임의로 패키지 설치 금지"처럼 AI가 절대 하지 말아야 할 행동을 명확히 금지하는 규칙입니다.
- [🟡 지시] **사고의 사슬**(CoT, Chain of Thought): AI가 성급하게 코드부터 내놓지 않고 "원인 분석 → 해결 방안 검토 → 수정"처럼 단계별 논리 과정을 거쳐 답하도록 유도하는 기법입니다.

### AI 에이전트와 Antigravity 도구
- [🟡 지시] **AI 에이전트**(AI Agent): 단순 질의응답을 넘어 스스로 계획을 세우고 파일 읽기/쓰기, 터미널 명령 실행, 웹 검색 등의 도구를 직접 호출해 과업을 수행하는 AI 시스템입니다.
- [🟢 원리] **에이전트 하네스**(Agent Harness): AI 모델(두뇌)이 실제 작업을 수행할 수 있도록 감싸서 도구, 규칙, 워크플로우, 메모리를 연결해 주는 실행 틀(프레임워크)입니다.
- [🟡 지시] **하네스 엔지니어링**(Harness Engineering): AI 에이전트가 한 번의 실행에서 길을 잃지 않고 작업할 수 있도록 필요한 도구(Tools), 허용된 행동(Actions), 그리고 "언제 완료(Done)로 볼 것인가"의 합격 기준을 갖춰 주는 설계 기술입니다.
- [🟢 원리] **루프 엔지니어링**(Loop Engineering): 잘 갖춰진 하네스 위에서 AI 에이전트가 한 번 답하고 끝내지 않고, 스스로 확인하고 고치기를 반복(Loop)하며 완료 조건을 만족할 때까지 자율적으로 일하게 만드는 설계 기술입니다.
- [🔴 생존] **인간의 최종 승인**(Human-in-the-Loop, HITL): AI 에이전트에게 모든 결정을 맡기지 않고, 파일 삭제·DB 변경·결제·배포 등 중요한 단계에서는 반드시 사람이 직접 검토하고 승인하도록 제어하는 안전 원칙입니다.
- [🟢 원리] **툴 콜링**(Tool Calling): AI가 외부 함수, API, 데이터베이스, 터미널 같은 실제 도구를 직접 호출하고 그 실행 결과를 받아 답변에 반영하는 기능입니다.
- [🟢 원리] **MCP**(Model Context Protocol): AI 모델이 외부 데이터 소스, 데이터베이스(Supabase), 결제 시스템, 문서 등과 표준화된 방식으로 통신할 수 있도록 연결하는 개방형 프로토콜입니다.
- [🟡 지시] **서브에이전트**(Subagent): 메인 대화창의 기억(컨텍스트)을 깔끔하게 유지하면서 코드 탐색(`research`)이나 브라우저 확인(`browser`) 같은 별도 작업을 독립된 새 세션에서 대신 처리하는 보조 에이전트입니다.
- [🟡 지시] **에이전트 오케스트레이션**(Agent Orchestration): 한 명의 설계자가 여러 역할의 AI 에이전트(기획, 프론트엔드, 백엔드, QA 등)에게 동시에 작업을 분배하고 조율·관리하는 기법입니다.
- [🟡 지시] **워크플로우**(Workflows): `.agents/workflows/*.md`에 정의해 두고, 사용자가 호출할 때만 불러와 실행하는 절차적 작업 매뉴얼입니다.
- [🟡 지시] **슬래시 커맨드**(Slash Command): 채팅창에 `/commit`, `/browser`처럼 `/`로 시작하는 단축 명령을 입력해 특정 워크플로우나 에이전트 기능을 즉시 실행하는 기능입니다.
- [🟡 지시] **에이전트 스킬**(Agent Skills / `SKILL.md`): 특정 작업에 필요한 지침과 참고 자료를 폴더 단위로 묶어 두고, 필요할 때 불러다 쓰는 재사용 가능한 지식 모듈입니다.
- [🟡 지시] **아티팩트**(Artifact): AI 에이전트가 작업 계획, 진행 체크리스트, 최종 요약 등을 깔끔하게 브리핑하기 위해 만들어주는 마크다운 보고서나 산출물입니다.
- [🟡 지시] **에디터 뷰**(Editor View): Antigravity에서 코드를 직접 보고 편집하는 화면입니다.
- [🟡 지시] **매니저 뷰**(Manager View): Antigravity에서 여러 AI 에이전트를 동시에 지휘·모니터링하는 오케스트레이션 화면입니다.
- [🟡 지시] **인라인 에디트**(Inline Edit, `Ctrl + I`): 메인 채팅창을 쓰지 않고 에디터 안에서 특정 코드 일부만 선택해 즉석으로 수정을 요청하는 간편 편집 기능입니다.

### 개발 기본 환경과 문서 문법
- [🟢 원리] **IDE**(Integrated Development Environment): 코드 편집기, 파일 탐색기, 터미널 실행 등을 한곳에서 지원하는 통합 개발 환경입니다. (예: VS Code, Antigravity)
- [🔴 생존] **터미널**(Terminal): 텍스트 명령어를 입력하고 실행 결과를 확인할 수 있는 명령줄 실행 창 프로그램입니다.
- [🟢 원리] **CLI**(Command-Line Interface): 마우스 클릭 대신 키보드로 텍스트 명령어를 입력해 컴퓨터나 개발 도구를 제어하는 인터페이스입니다.
- [🟢 원리] **GUI**(Graphical User Interface): 터미널과 반대로, 마우스와 창·버튼·아이콘 같은 그래픽 요소를 보며 직관적으로 조작하는 화면입니다.
- [🟡 지시] **마크다운**(Markdown): `#`으로 제목을, `**`로 굵은 글씨를 표시하는 간단한 텍스트 문서 문법입니다. AI에게 요구사항을 정리해 전달할 때 가장 많이 쓰입니다.
- [🟡 지시] **GFM**(GitHub Flavored Markdown): 기본 마크다운에 표, 체크리스트, 코드 블록 등 확장 문법을 더한 GitHub 표준 마크다운 규격입니다.
- [🔴 생존] **의존성**(Dependency): 내 프로젝트가 동작하기 위해 가져다 쓰는 외부 라이브러리나 패키지 자체를 의미합니다.
- [🔴 생존] **패키지 매니저**(Package Manager): 프로젝트에 필요한 외부 라이브러리(의존성)를 설치·업데이트·버전 관리하는 도구입니다. (JavaScript: `npm`, Python: `pip`, `uv`)

## 3. 기획 · 웹 기초 · UI 디자인 용어

> *"만들고 싶은 서비스의 뼈대를 기획하고, AI에게 화면 구성을 정확히 설명할 때 꼭 쓰는 단어들입니다."*

### 기획 및 설계 기초
- [🟡 지시] **PRD**(Product Requirements Document, 요구사항 정의서): 만들고자 하는 서비스의 목적, 핵심 기능, 사용자 흐름, 제약 조건을 체계적으로 정리한 기획 문서입니다.
- [🟡 지시] **개념 증명**(PoC, Proof of Concept): 본격적인 최소 기능 제품(MVP)을 만들기 전에, 핵심 아이디어나 외부 API·AI 기능이 실제로 동작하는지 가장 작고 빠르게 시험해 보는 단계입니다.
- [🟡 지시] **MVP**(Minimum Viable Product, 최소 기능 제품): 모든 기능을 한꺼번에 만들지 않고, 핵심 가치만 담아 가장 빠르게 동작을 확인하기 위해 만드는 최소 단위의 제품입니다.
- [🟡 지시] **사용자 흐름**(User Flow): 사용자가 목적을 달성하기 위해 서비스 안의 여러 화면을 이동하는 동선과 단계입니다.
- [🟡 지시] **와이어프레임**(Wireframe): 화려한 색상이나 디자인을 입히기 전에 화면 배치와 정보 구조를 선과 상자로 대략적으로 그린 설계도입니다.
- [🟡 지시] **클린 아키텍처**(Clean Architecture): 비즈니스 핵심 로직과 외부 프레임워크·DB·UI를 계층별로 엄격히 분리하고 의존성 방향을 안쪽으로 고정하여, AI가 코드 구조를 쉽게 파악(가이드 정확도 향상)하고 유지보수성을 높이는 설계 원칙입니다.
- [🟡 지시] **단일 진실 공급원**(SSOT, Single Source of Truth): 같은 설정·규칙·데이터 구조를 여러 파일에 중복 작성해 서로 어긋나지 않도록, 프로젝트 안에서 "유일한 기준 정답으로 삼는 문서나 데이터 원천"을 하나로 고정하는 원칙입니다.

### 웹의 3대 기초와 주요 도구
- [🟢 원리] **HTML5**: 웹 페이지의 뼈대와 콘텐츠 구조(제목, 글, 버튼, 입력창 등)를 정의하는 언어입니다.
- [🟢 원리] **CSS3**: HTML 요소의 색상, 크기, 여백, 배치 등 시각적 스타일을 꾸미는 언어입니다.
- [🟢 원리] **JavaScript**: 웹 페이지가 사용자 클릭에 반응하고 움직이도록 동적인 동작과 로직을 부여하는 프로그래밍 언어입니다.
- [🟢 원리] **TypeScript**: JavaScript에 데이터 타입 검사 기능을 추가해 실행 전에 오타나 타입 오류를 미리 잡아주는 언어입니다.
- [🟡 지시] **React**: 화면을 재사용 가능한 부품(컴포넌트) 단위로 조립해 만드는 대표적인 자바스크립트 UI 라이브러리입니다.
- [🟡 지시] **Next.js**: React를 기반으로 서버 렌더링, 라우팅 등 완성도 높은 풀스택 웹 앱을 쉽게 구축할 수 있게 해주는 프레임워크입니다.
- [🟡 지시] **Tailwind CSS**: 별도의 스타일 파일을 길게 쓰지 않고 HTML 태그 안에 짧은 클래스명만 적어 빠르게 디자인을 입히는 CSS 도구입니다.

### 화면과 UI 디자인 핵심 용어
- [🟡 지시] **반응형 디자인**(Responsive Design): 스마트폰, 태블릿, PC 등 화면 크기에 맞춰 레이아웃이 자동으로 알맞게 변하는 웹 설계 방식입니다.
- [🟡 지시] **디자인 시스템**(Design System): 서비스 전체에서 일관된 느낌을 주도록 색상, 글꼴, 버튼 규격과 디자인 원칙을 정리한 가이드(`DESIGN.md`)입니다.

#### 꼭 알아둘 UI 부품 이름 (AI에게 화면 수정을 지시할 때 유용합니다)
- [🟡 지시] **내비게이션 바**(Navbar): 웹사이트 상단에 배치되는 주요 메뉴 이동 줄입니다.
- [🟡 지시] **사이드바**(Sidebar): 화면 좌측이나 우측에 고정되어 메뉴나 보조 정보를 보여주는 패널입니다.
- [🟡 지시] **모달**(Modal): 현재 화면 위에 어두운 배경과 함께 뜨는 팝업 창입니다.
- [🟡 지시] **드로어**(Drawer): 화면 옆쪽에서 스르르 밀려 나오는 슬라이드 패널입니다.
- [🟡 지시] **토스트 메시지**(Toast): "저장되었습니다"처럼 화면 구석에 잠깐 떴다가 자동으로 사라지는 알림 배너입니다.
- [🟡 지시] **셀렉트 박스**(Select Box / 드롭다운): 클릭하면 아래로 선택 목록이 펼쳐지는 입력 상자입니다.
- [🟡 지시] **체크박스**(Checkbox): 여러 항목을 동시에 복수 선택할 때 쓰는 네모 선택 상자입니다.
- [🟡 지시] **라디오 버튼**(Radio Button): 여러 보기 중 단 하나만 선택해야 할 때 쓰는 동그란 선택 버튼입니다.
- [🟡 지시] **토글 스위치**(Toggle Switch): 다크 모드 설정처럼 기능을 켜고 끄는(On/Off) 스위치 요소입니다.
- [🟡 지시] **스피너**(Spinner): 데이터를 불러오는 중임을 알려주는 회전형 로딩 아이콘입니다.
- [🟡 지시] **스켈레톤 스크린**(Skeleton Screen): 실제 콘텐츠가 로딩되는 동안 레이아웃 형태를 미리 보여주는 회색 뼈대 화면입니다.
- [🟡 지시] **CTA**(Call-To-Action): "지금 시작하기", "결제하기"처럼 사용자의 핵심 행동을 유도하는 강조 버튼입니다.

## 4. 서버 · API · 데이터베이스 기초

> *"내 화면(프론트엔드)과 뒷단(백엔드·DB)이 어떻게 데이터를 주고받고 저장하는지 이해하는 기초 개념입니다."*

- [🟢 원리] **클라이언트-서버 구조**(Client-Server Architecture): 사용자가 보고 조작하는 앞단(클라이언트/프론트엔드)과 데이터를 계산·저장하는 뒷단(서버/백엔드)이 네트워크로 요청과 응답을 주고받는 구조입니다.
- [🟡 지시] **REST API**: 프론트엔드와 백엔드가 HTTP 규칙과 URL을 통해 데이터를 주고받도록 설계한 표준 웹 API 방식입니다.
- [🟢 원리] **엔드포인트**(Endpoint): API가 외부의 요청을 받아들이는 구체적인 URL 경로 주소입니다.
- [🟢 원리] **오픈 API**(Open API): 기상청 날씨, 공공데이터처럼 누구나 일정 규칙에 따라 가져다 쓸 수 있도록 외부에 공개된 데이터 창구입니다.
- [🟢 원리] **HTTP 메서드**: 서버에 요청을 보낼 때의 목적을 구분하는 방식으로, 조회(`GET`), 생성(`POST`), 수정(`PUT`/`PATCH`), 삭제(`DELETE`)가 대표적입니다.
- [🟢 원리] **HTTP 상태 코드**(Status Code): 서버가 요청을 처리한 결과를 알려주는 3자리 숫자입니다. (`200` 성공, `400` 잘못된 요청, `401`/`403` 로그인·권한 없음, `404` 주소를 찾을 수 없음, `500` 서버 내부 오류)
- [🟢 원리] **JSON**(JavaScript Object Notation): `{"이름": "홍길동", "나이": 20}`처럼 키-값 쌍으로 데이터를 표현해 웹과 API 통신에서 가장 널리 쓰이는 텍스트 형식입니다.
- [🟡 지시] **CRUD**: 모든 데이터 서비스의 4가지 기본 기능인 생성(Create), 조회(Read), 수정(Update), 삭제(Delete)를 뜻합니다.
- [🟢 원리] **데이터베이스**(Database): 회원 정보, 게시글, 주문 내역 같은 데이터를 체계적으로 영구 저장·관리하는 데이터 저장소입니다.
- [🟢 원리] **SQL**(Structured Query Language): 관계형 데이터베이스에서 데이터를 조회·삽입·수정·삭제할 때 사용하는 표준 언어입니다.
- [🟡 지시] **스키마**(Schema): 데이터베이스 테이블의 구조, 열(Column)의 자료형, 제약조건 등을 정의한 청사진입니다.
- [🟢 원리] **BaaS**(Backend-as-a-Service): 백엔드 서버를 직접 구축하지 않고도 데이터베이스, 회원 인증, 파일 저장소 등을 API 형태로 바로 제공하는 클라우드 서비스 모델입니다.
- [🟢 원리] **Supabase**(수파베이스): PostgreSQL 데이터베이스, 인증(Auth), 스토리지, 실시간 구독 기능을 한 번에 제공하는 대표적인 오픈소스 기반 BaaS 플랫폼입니다.

## 5. 오류 해결 · 보안 · Git · 배포

> *"문제가 생겼을 때 당황하지 않고 원인을 찾고, 비밀 정보를 지키며, 내 서비스를 인터넷에 공개하는 필수 개념입니다."*

### 오류 해결과 품질 관리
- [🔴 생존] **트러블슈팅**(Troubleshooting): 프로그램 실행 중 발생한 오류나 버그의 원인을 추적해 정상 상태로 고치는 문제 해결 과정입니다.
- [🔴 생존] **로깅**(Logging): 프로그램이 동작한 이력과 에러 메시지를 기록으로 남겨 문제 원인을 파악할 수 있게 하는 작업입니다.
- [🟡 지시] **리팩토링**(Refactoring): 겉으로 보이는 기능은 똑같이 유지하면서, 내부 코드를 더 읽기 쉽고 깔끔한 구조로 정리하는 작업입니다.
- [🟡 지시] **TDD**(Test-Driven Development, 테스트 주도 개발): 기능을 만들기 전에 "이 조건을 통과해야 성공"이라는 테스트 기준부터 먼저 세우고 코드를 작성하는 방식입니다. AI에게 명확한 합격 기준을 줄 때 매우 효과적입니다.
- [🟡 지시] **단위 테스트**(Unit Test): 개별 함수나 작은 모듈이 의도대로 동작하는지 독립적으로 검증하는 테스트입니다.
- [🔴 생존] **코드 리뷰**(Code Review): 작성된 코드의 버그, 보안 취약점, 아키텍처 준수 여부를 동료나 시니어 페르소나 AI가 점검하는 활동입니다.
- [🔴 생존] **검증 루프**(Verification Loop): 코드 수정 후 `git diff --stat` 확인이나 테스트 재실행 같은 자가 검증 절차를 반복하도록 강제하는 품질 통제 전략입니다.
- [🟡 지시] **더미 데이터**(Dummy Data): 실제 사용자의 개인정보를 쓰지 않고 개발과 테스트를 진행하기 위해 대신 만들어 넣는 가짜 데이터입니다.

### 초심자가 꼭 지켜야 할 보안 기초
- [🔴 생존] **환경 변수**(`.env`): API 키나 DB 비밀번호처럼 민감한 설정값을 소스 코드와 분리해 보관·주입하는 변수 및 설정 파일입니다.
- [🔴 생존] **하드코딩**(Hardcoding): 변경될 수 있는 설정값이나 민감한 API 키를 `.env` 등으로 분리하지 않고 소스 코드 내부에 직접 박아 넣는 나쁜 습관입니다.
- [🔴 생존] **클라이언트 키**(Client Key): 브라우저 화면 코드에 들어가 외부에 공개되어도 괜찮은 공개용 API 키입니다.
- [🔴 생존] **시크릿 키**(Secret Key): 절대 외부(브라우저·GitHub 등)에 노출되면 안 되며 신뢰할 수 있는 백엔드 서버에서만 몰래 써야 하는 비밀 키입니다.
- [🔴 생존] **인증**(Authentication): 사용자가 누구인지 로그인 등을 통해 신원을 확인하는 절차입니다.
- [🔴 생존] **인가**(Authorization): 인증된 사용자가 특정 페이지나 데이터에 접근·수정할 권한이 있는지 확인하는 절차입니다.
- [🔴 생존] **프롬프트 인젝션**(Prompt Injection): 외부 문서나 검증되지 않은 파일 안에 악의적인 지시를 숨겨 두어, AI 에이전트가 `.env` 유출 같은 위험한 행동을 하도록 속이는 보안 공격입니다.

### Git 버전 관리와 인터넷 배포
- [🔴 생존] **Git**: 소스 코드의 변경 이력을 내 컴퓨터에 세이브포인트처럼 기록·추적·관리하는 분산 버전 관리 시스템입니다.
- [🔴 생존] **GitHub**: Git 저장소를 클라우드에 올려 백업하고 코드 리뷰나 협업을 지원하는 플랫폼입니다.

#### 초심자 필수 Git 명령어 및 설정
- [🔴 생존] `git init`: 현재 프로젝트 폴더에서 Git 버전 관리를 처음 시작(초기화)하는 명령어입니다.
- [🔴 생존] `git status`: 어떤 파일이 새로 생기거나 수정되었는지 현재 작업 상태를 확인하는 명령어입니다.
- [🔴 생존] `git add`: 다음 세이브포인트(커밋)에 기록할 변경 파일들을 장바구니(스테이징 영역)에 담는 명령어입니다.
- [🔴 생존] `git commit`: 담은 변경 사항을 메시지 설명과 함께 하나의 세이브포인트로 확정 저장하는 명령어입니다.
- [🔴 생존] `git push`: 내 컴퓨터에 저장한 커밋 이력을 GitHub 클라우드 저장소로 업로드하는 명령어입니다.
- [🔴 생존] `git pull`: GitHub 클라우드에 올라간 최신 변경 사항을 내 컴퓨터로 내려받아 합치는 명령어입니다.
- [🔴 생존] `git branch`: 기존 코드에 영향을 주지 않고 새로운 기능을 실험하기 위한 독립 작업 분기를 만드는 명령어입니다.
- [🟡 지시] **Pull Request**(PR): 수정한 브랜치나 Fork 저장소의 변경 사항을 원본 저장소에 병합해 달라고 요청하는 협업 흐름입니다.
- [🔴 생존] `.gitignore`: `.env` 비밀 파일이나 무거운 설치 폴더(`node_modules/`, `.venv/`)가 GitHub에 올라가지 않도록 제외 목록을 적어두는 설정 파일입니다.

#### 배포 및 복구
- [🔴 생존] **롤백**(Rollback): 코드를 잘못 고쳤거나 배포 후 문제가 생겼을 때, 정상적으로 동작하던 이전 버전으로 안전하게 되돌리는 복구 작업입니다.
- [🔴 생존] **배포**(Deploy): 내 컴퓨터에서만 실행되던 웹이나 프로그램을 클라우드 서버에 올려 누구나 인터넷 주소(URL)로 접속할 수 있게 공개하는 과정입니다.
- [🟢 원리] **CI/CD**: 코드 변경 사항을 GitHub에 `push`할 때마다 자동으로 빌드·테스트·배포까지 이어지게 만드는 자동화 파이프라인입니다. (예: Vercel, Render, Cloudflare Pages)
