# AI 코딩 환경 보안 및 안전 관리 핵심 정리

## 1. 코드 및 개인정보 유출 관리
- **문제점**: AI 통합 개발 환경(IDE)은 코드를 LLM 서버로 전송하여 추론하므로 외부 유출, 모델 학습 데이터 활용, 서버 로그 저장 위험이 있음.
- **주의 대상**: 주민등록번호, 전화번호, 사내 IP 등 민감 개인정보 및 내부 정보가 AI 문맥(Context)으로 포함되지 않도록 각별히 주의해야 함.
- **대응 방법**:
  - AI 에이전트가 읽지 말아야 할 파일·폴더는 ignore 목록에 명시적으로 추가하여 인덱싱을 제외함.
  - **주의 (중요)**: 안티그래비티는 `.cursorignore`가 없고 Git의 `.gitignore`를 인덱싱 제외에 참고하지만, **에이전트가 도구(`view_file`)로 접근하거나 사용자가 `@`로 호출하면 `.gitignore` 대상 파일(예: `.env`)도 읽을 수 있음**. 따라서 `.gitignore` 설정만 믿고 민감 파일을 방치하면 안 되며, 룰(`AGENTS.md`)에 접근 금지를 명시하거나 환경 변수 관리에 각별히 유의해야 함.

## 2. API 키 노출 관리
- **문제점**:
  - 코드에 하드코딩된 API 키, DB 접속 정보는 분석 과정에서 AI 답변에 노출되거나 외부로 유출될 위험 있음.
  - 외부에서 복사해 온 프롬프트에 해커가 심어둔 악의적 지시(특정 URL로 API 키 전송 유도 등)가 포함될 수 있음.
- **대응 방법**:
  - 외부에서 가져온 프롬프트는 사용 전 전체 문맥을 반드시 확인함.
  - 모든 API 키와 접속 정보는 코드에서 분리하여 `.env` 파일로 관리함.
  - 보안이 필요한 파일은 AI ignore 목록에 추가하여 에이전트 접근을 차단함.

## 3. 파일 손상 관리
- **문제점**:
  - 최신 AI IDE는 파일 생성·수정·삭제 및 터미널 명령어 실행 권한까지 보유함.
  - 부주의하게 승인할 경우 중요 설정 파일 삭제, 기존 로직 덮어쓰기, `rm -rf` 같은 치명적 명령어 실행으로 로컬 환경이 손상될 수 있음.
- **대응 방법**:
  - AI 에이전트가 제안한 변경 사항이나 터미널 명령어는 적용 전 반드시 꼼꼼히 확인하는 습관을 가짐.
  - 작업 단위마다 깃(Git) 커밋을 남겨 언제든 이전 정상 상태로 복구할 수 있도록 관리함.
