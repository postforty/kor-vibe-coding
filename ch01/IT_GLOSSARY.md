## 1. AI · LLM · 바이브 코딩

### 핵심 패러다임 및 개념
- [★★★] **바이브 코딩**(Vibe Coding): 개발자가 코드를 한 줄씩 직접 타이핑하는 대신, 자연어로 요구사항과 설계서(프롬프트)를 작성해 AI 에이전트에게 구현을 지시하고 결과물을 검증하는 설계자 중심의 개발 방식입니다. (안드레이 카파시가 처음 제시한 용어)
- [★★★] **에이전틱 엔지니어링**(Agentic Engineering): 단순한 코드 생성 요청을 넘어, AI 에이전트에게 명세(Spec)와 테스트 케이스를 제공하고 계획·구현·검증·배포의 전체 소프트웨어 엔지니어링 수명주기를 지휘하는 개발 패러다임입니다.
- [★★☆] **에이전트 우선 아키텍처**(Agent-First Architecture): 사람(개발자)이 직접 코드를 편집하는 기존 IDE 중심 구조에서 벗어나, AI 에이전트가 주도적으로 작업 계획을 세우고 도구를 호출해 실행하는 개발 환경 구조입니다.
- [★☆☆] **AX**(AI Transformation): 기업의 업무 프로세스와 개발 워크플로우 전반을 AI 중심으로 전환하여 생산성을 극대화하는 디지털 전환 전략입니다.
- [★☆☆] **로우코드/노코드**(Low-code/No-code): 코드를 직접 작성하지 않고 시각적 블록 조립이나 드래그 앤 드롭만으로 앱을 만드는 개발 방식으로, 자연어로 실제 소스 코드를 생성하는 바이브 코딩과 구분됩니다.

### 대규모 언어 모델(LLM) 원리 및 파라미터
- [★★★] **LLM**(Large Language Model, 대규모 언어 모델): 방대한 텍스트 데이터를 학습하여 문맥을 이해하고 자연어 및 코드를 생성하는 거대 인공지능 모델입니다.
- [★★★] **토큰**(Token): LLM이 텍스트를 처리하고 과금하는 기본 단위(단어 또는 형태소 조각)입니다.
- [★★★] **토큰 이코노미**(Token Economy): AI 모델별 특성과 비용을 이해하고 토큰을 전략적으로 투입해 개발 생산성과 비즈니스 부가가치를 극대화하는 사고방식 및 운영 전략입니다.
- [★★★] **할루시네이션**(Hallucination, 환각): AI가 사실이 아니거나 존재하지 않는 라이브러리·API·정보를 확률적으로 그럴듯하게 지어내어 답변하는 현상입니다.
- [★★☆] **다음 토큰 예측**(Next-Token Prediction): LLM이 입력된 문맥 뒤를 이을 가장 확률 높은 다음 단어(토큰)를 순차적으로 계산해 문장을 생성하는 핵심 동작 원리입니다.
- [★★☆] **비결정론적 생성**(Non-deterministic / 확률적 생성): 동일한 프롬프트를 입력해도 매번 확률 계산(주사위 굴리기)에 의해 서로 다른 구조나 표현의 결과물이 생성되는 LLM의 특성입니다.
- [★★☆] **추론/사고 과정**(Reasoning / Thinking): 모델이 Inference(실행) 중 최종 답변을 내놓기 전에 내부적으로 논리적 단계를 밟아 생각하는 과정입니다. (`enable_thinking`, `reasoning_content`)
- [★★☆] `temperature`: 모델이 다음 토큰을 선택할 때의 무작위성(창의성 대 일관성)을 조절하는 샘플링 파라미터입니다.
- [★★☆] **스트리밍**(Streaming): AI가 전체 답변을 완성할 때까지 기다리지 않고, 생성되는 토큰 조각(Chunk)을 실시간으로 순차 출력하는 전송 방식입니다.
- [★☆☆] **파운데이션 모델**(Foundation Model): 다양한 작업에 범용적으로 활용할 수 있도록 대규모 데이터로 사전 학습된 기반 AI 모델입니다. (예: Gemini, Claude, GPT, DeepSeek, Nemotron, Gemma, Llama)
- [★☆☆] **벤치마크**(Benchmark): AI 모델의 추론, 코딩, 수학 등 실제 성능을 객관적인 지표로 비교·평가하는 표준 시험입니다.
- [★☆☆] **모델 추론/서빙**(Inference): 학습(Training)이 끝난 모델에 입력을 넣어 출력을 생성·계산하는 실행 과정 전체입니다. (논리적 사고 과정을 뜻하는 Reasoning과 구분되며, 추론 서버·엔진·플랫폼 맥락의 '추론'이 여기에 해당합니다.)
- [★☆☆] `top_p`: 누적 확률이 상위 `p`에 해당하는 후보 토큰들만 남기고 선택 범위를 제한하는 샘플링 파라미터입니다.
- [★☆☆] `max_completion_tokens`: AI 모델이 한 번의 응답에서 생성할 수 있는 최대 토큰 수를 제한하는 설정입니다.

### 프롬프트 엔지니어링 및 컨텍스트 관리
- [★★★] **프롬프트**(Prompt): AI 모델에게 작업을 지시하거나 질문을 던지는 자연어 입력문입니다.
- [★★★] **프롬프트 엔지니어링**(Prompt Engineering): AI로부터 원하는 정확하고 일관된 결과물을 얻기 위해 입력 문장의 구조, 제약, 예시를 정교하게 설계하는 기술입니다.
- [★★★] **컨텍스트 엔지니어링**(Context Engineering): 프롬프트 문장만 다듬는 수준을 넘어, AI 모델이 현재 시점에 컨텍스트 윈도우 안에서 최적의 판단을 내릴 수 있도록 시스템 프롬프트·규칙·참조 문서(RAG)·도구 실행 결과·대화 이력 등 입력 정보 전체를 동적으로 선별·구성하는 기술입니다.
- [★★★] **시스템 프롬프트**(System Prompt / System Instructions): 대화 전반에 걸쳐 AI의 역할, 어조, 행동 규칙, 제약 조건을 최우선으로 규정하는 배경 지시문입니다.
- [★★★] **사고의 사슬**(CoT, Chain of Thought): AI가 성급하게 결론이나 코드를 내놓지 않고 "원인 분석 → 부작용 검토 → 해결 코드"처럼 단계별 논리 과정을 거쳐 답하도록 유도하는 기법입니다.
- [★★★] **네거티브 제약**(Negative Constraints): "코드 생략 금지", "임의 패키지 설치 금지" 등 AI가 절대 하지 말아야 할 행동을 명확히 금지하는 프롬프트 규칙입니다.
- [★★★] **컨텍스트 윈도우**(Context Window): AI 모델이 한 번의 대화 세션에서 기억하고 동시에 처리할 수 있는 입력·출력 텍스트의 최대 용량입니다.
- [★★★] **컨텍스트 격리**(Context Isolation): 메인 작업 세션의 대화 기록을 오염시키지 않기 위해, 탐색이나 리서치 작업을 별도의 깨끗한 세션(서브에이전트 등)으로 분리하는 전략입니다.
- [★★☆] **페르소나 프롬프팅**(Persona Prompting): AI에게 특정 전문가(예: 시니어 코드 리뷰어, 사서, 보안 감사자)의 역할을 부여해 답변의 관점과 전문성을 높이는 기법입니다.
- [★★☆] **퓨샷 프롬프팅**(Few-shot Prompting): AI가 원하는 패턴과 출력 형식을 학습할 수 있도록 프롬프트 안에 몇 가지 입출력 예시를 함께 제시하는 기법입니다.
- [★★☆] **TCREI 프레임워크**: 구글에서 제안하는 프롬프트 작성 표준 구조로 **Task**(작업), **Context**(맥락), **Reference**(참조), **Evaluate**(평가), **Iterate**(반복)의 약자입니다. (`RTF` 등 유사 프레임워크 포함)
- [★★☆] **구조화된 출력**(Structured Output): 인사말이나 마크다운 기호 없이 API나 프로그램이 바로 파싱할 수 있는 순수 JSON 등 고정된 스키마 형태로만 출력을 강제하는 기법입니다.
- [★★☆] **컨텍스트 오염/비대화**(Context Bloat / Context Window Pollution): 불필요한 로그, 파일 전문, 긴 대화 내역이 컨텍스트 윈도우에 누적되어 AI의 집중도와 응답 품질이 떨어지는 현상입니다.
- [★★☆] **프롬프트 인젝션**(Prompt Injection): 외부 문서, 웹사이트, 검증되지 않은 스킬 파일 등에 악의적인 명령을 숨겨두어 AI 에이전트가 원래 의도와 다른 위험한 동작(예: `.env` 탈취)을 하도록 유도하는 보안 공격입니다.
- [★☆☆] **제로샷 프롬프팅**(Zero-shot Prompting): 별도의 입출력 예시 없이 바로 질문이나 지시만 전달해 답변을 유도하는 방식입니다.
- [★☆☆] **Step-Back 프롬프팅**: AI가 바로 세부 답을 내놓지 않고 문제의 근본 원리나 상위 개념부터 먼저 정리한 뒤 답하도록 유도하는 고전 프롬프팅 기법입니다.
- [★☆☆] **Self-Consistency**: 동일한 질문에 대해 여러 번 추론 경로를 생성하게 한 뒤, 다수결 투표를 통해 가장 일관된 정답을 선택하던 고전 프롬프팅 기법입니다.

## 2. AI 에이전트 · 오케스트레이션 · Antigravity 생태계

### 에이전트 아키텍처 및 제어
- [★★★] **AI 에이전트**(AI Agent): 단순 질의응답을 넘어 스스로 목표를 계획하고, 파일 읽기/쓰기·터미널 실행·웹 검색 등의 도구를 호출해 자율적으로 과업을 수행하는 AI 시스템입니다.
- [★★★] **에이전트 오케스트레이션**(Agent Orchestration): 한 명의 설계자가 여러 역할의 AI 에이전트(기획, 프론트엔드, 백엔드, QA 등)에게 동시에 작업을 분배하고 조율·관리하는 기법입니다.
- [★★★] **서브에이전트**(Subagent): 메인 에이전트의 컨텍스트를 보존하고 복잡한 작업을 병렬로 처리하기 위해 백그라운드의 독립된 깨끗한 세션(Clean Slate)에서 비동기로 실행되는 자식 에이전트입니다.
- [★★★] **인간의 최종 승인**(Human-in-the-Loop, HITL): AI 에이전트에게 모든 실행을 일임하지 않고, 파기성 명령(파일 삭제·DB 변경·배포 등)이나 핵심 의사결정 시점에서는 반드시 사람이 검토·승인한 뒤 진행하도록 통제하는 안전 원칙입니다.
- [★★☆] **에이전트 하네스**(Agent Harness): AI 모델(두뇌)을 감싸 실제 작업 환경과 연결하고, 규칙·도구·워크플로우·메모리를 제어하는 실행 프레임워크입니다. ($\text{Agent} = \text{Model} + \text{Harness}$)
- [★★☆] **하네스 엔지니어링**(Harness Engineering): AI 모델이 단일 실행(Single Run)에서 과업을 완수할 수 있도록 도구(Tools)·허용 동작(Actions)·가드레일·메모리 그리고 명확한 완료 판정 기준("Done")과 검증 절차를 체계적으로 설계·장착하는 기술입니다.
- [★★☆] **루프 엔지니어링**(Loop Engineering): 하네스로 무장한 AI 에이전트가 사람의 지속적인 개입 없이 스스로 계획·실행·오류 수정·완료 확인을 반복(Loop)하며 최종 목표에 도달할 때까지 자율적으로 구동되도록 제어 흐름과 종료 조건을 설계하는 기술입니다.
- [★★☆] **내장 서브에이전트**(Built-in Subagent): Antigravity에 기본 탑재된 전담 에이전트입니다. (`research`: 코드베이스 탐색, `browser`: 브라우저 제어 및 테스트, `self`: 메인 에이전트 복제)
- [★★☆] **커스텀 서브에이전트**(Custom Subagent): 사용자가 `.agents/agents/*.md` 경로에 YAML Frontmatter와 시스템 프롬프트를 작성해 직접 정의하는 역할별 전문 에이전트입니다.
- [★★☆] **에이전트 간 통신**(Inter-Agent Communication): 에이전트들이 고유 대화 식별자(Conversation ID)를 통해 서로 지시나 결과를 주고받는 구조입니다.
- [★★☆] **속도 편향**(Speed Bias): AI 에이전트가 안전 가이드라인을 인지하고도 작업을 빨리 끝내려는 경향 때문에 위험한 지름길(예: 대형 파일 정규식 일괄 치환)을 선택하는 현상입니다.
- [★★☆] **소프트 가드레일**(Soft Guardrail): 자연어로 작성된 규칙이나 프롬프트 지침을 뜻하며, 에이전트의 오작동을 물리적으로 100% 차단하지는 못하는 한계를 지닙니다.
- [★☆☆] **중첩 깊이 제한**(Nesting Depth Limit): 서브에이전트가 또 다른 서브에이전트를 연쇄 호출할 수 있는 최대 단계 제한입니다. (Antigravity 기준 최대 10단계)
- [★☆☆] **자동 깨어남**(Auto-Wake): 작업을 마치고 유휴(Idle) 상태로 대기 중인 서브에이전트가 Conversation ID 기반 메시지를 수신하면 즉시 실행(Running) 상태로 재개되는 메커니즘입니다.
- [★☆☆] **헤드리스 에이전트**(Headless Agent): 그래픽 화면(UI) 없이 CLI나 Python SDK 스크립트를 통해 백그라운드에서 프로그래밍 방식으로 실행되는 에이전트입니다.
- [★☆☆] **멀티턴 세션**(Multi-turn Session): 이전 대화의 맥락을 세션별로 저장·조회하며 연속적으로 대화를 이어가는 방식입니다.

### 도구 연동 · 규격 · Antigravity 기능
- [★★★] `AGENTS.md`: 프로젝트 루트에 위치하여 AI 에이전트(Antigravity 등)가 프로젝트 전반에서 준수해야 할 전역 행동 지침, 보안 제약, 아키텍처 규칙을 선언하는 표준 문서입니다.
- [★★★] **규칙**(Rules): `.agents/rules/*.md` 등에 저장되어 매 대화 턴마다 컨텍스트에 상시 자동 포함되는 프로젝트의 고정 원칙과 금지 사항입니다.
- [★★★] **워크플로우**(Workflows): `.agents/workflows/*.md`에 정의해 두고, 사용자가 `/커맨드명` 형태로 호출할 때만 온디맨드로 로드되는 절차적 작업 매뉴얼입니다.
- [★★★] **슬래시 커맨드**(Slash Command): 채팅창에 `/`로 시작하는 명령어를 입력해 특정 워크플로우나 에이전트 기능을 즉시 실행하는 단축 명령입니다. (예: `/commit`, `/tdd`, `/grill-me`, `/research`, `/teamwork`, `/browser`, `/agents`)
- [★★★] **에이전트 스킬**(Agent Skills / `SKILL.md`): 특정 작업에 대한 지침, 모범 사례, 실행 스크립트(`scripts/`), 리소스(`resources/`)를 폴더 단위로 패키징한 재사용 가능한 지식 모듈입니다.
- [★★☆] **툴 콜링**(Tool Calling / 도구 바인딩): LLM이 외부 함수, API, 데이터베이스, 시계, 터미널 등 실제 도구를 직접 호출하고 그 실행 결과를 받아 답변에 반영하는 기능입니다.
- [★★☆] **MCP**(Model Context Protocol): AI 모델이 외부 데이터 소스, 데이터베이스(Supabase), 결제 시스템(토스페이먼츠), 문서(Context7) 등과 표준화된 방식으로 통신할 수 있도록 연결하는 개방형 프로토콜입니다.
- [★★☆] **점진적 공개**(Progressive Disclosure): 에이전트가 대화 시작 시 모든 스킬의 본문을 읽지 않고 이름·설명만 확인(Discovery)한 뒤, 필요할 때만 전체 `SKILL.md`를 읽어(Activation) 실행하는 토큰 절약 패턴입니다.
- [★★☆] **아티팩트**(Artifact): Antigravity 에이전트가 작업 과정과 결과를 체계적으로 브리핑하기 위해 생성하는 마크다운 보고서, 구현 계획서, 작업 목록, 브라우저 녹화 영상 등의 산출물입니다.
- [★★☆] **플러그인**(Plugin): 스킬·에이전트·규칙·MCP 서버를 하나로 묶어 설치·관리할 수 있는 확장 번들입니다.
- [★★☆] **에디터 뷰**(Editor View): Antigravity에서 코드를 직접 보고 편집하는 화면입니다.
- [★★☆] **매니저 뷰**(Manager View): Antigravity에서 여러 AI 에이전트를 동시에 지휘·모니터링하는 오케스트레이션 화면입니다.
- [★★☆] **인라인 에디트**(Inline Edit, `Ctrl + I`): 사이드바 메인 채팅창의 컨텍스트를 소모하지 않고 에디터 내 특정 코드 블록만 선택해 즉석에서 수정하는 경량 편집 기능입니다.
- [★★☆] **Antigravity CLI**(`agy`): 터미널 명령어로 Antigravity 에이전트를 제어하고 실행할 수 있는 커맨드라인 인터페이스입니다.
- [★☆☆] `CLAUDE.md`: Claude Code 환경에서 프로젝트 루트에 두어 AI 에이전트에게 전역 행동 지침, 보안 제약, 아키텍처 규칙을 전달하는 표준 문서입니다.
- [★☆☆] **생명주기 훅**(Lifecycle Hook): 에이전트나 프로그램 동작의 특정 시점(시작, 도구 실행 전후, 종료 등)에 개입해 사용자 정의 로직을 실행하는 훅 메커니즘입니다.
- [★☆☆] **Python SDK**(`google-antigravity`): 파이썬 스크립트를 통해 Antigravity 에이전트 자동화 파이프라인을 구축할 수 있는 개발 키트입니다.

### RAG · 벡터 DB · AI 프레임워크 및 생태계 도구
- [★★☆] **RAG**(Retrieval-Augmented Generation, 검색 증강 생성): LLM이 학습하지 않은 최신 정보나 사내·개인 지식 베이스를 외부 데이터베이스에서 먼저 검색한 뒤, 그 근거를 바탕으로 답변을 생성하는 파이프라인 기술입니다.
- [★★☆] **랭체인**(LangChain): LLM과 외부 데이터, 프롬프트 템플릿, 체인(Chain), 리트리버(Retriever), 출력 파서(Output Parser), 에이전트를 연결해 AI 애플리케이션을 구축하는 프레임워크입니다.
- [★★☆] **멀티 벤더**(Multi-vendor): 특정 AI 회사 하나에 종속되지 않고 여러 공급자(Google, Anthropic, OpenAI 등)의 AI 모델을 함께 활용하는 구성 방식입니다.
- [★★☆] **모델 스위칭**(Model Switching): 작업 난이도와 비용(토큰 이코노미)에 따라 Gemini Flash/Pro, Claude, GPT, NVIDIA NIM, Ollama 등 최적의 모델로 유연하게 교체하며 사용하는 전략입니다.
- [★★☆] **Cursor**: AI 에이전트 기능과 코드 편집 환경을 결합한 AI 코딩 에디터로, 프로젝트 내에서 비교·언급됩니다.
- [★☆☆] **임베딩**(Embedding): 텍스트나 문서의 의미를 AI가 수학적 거리(유사도)로 계산할 수 있도록 고차원 숫자 벡터(배열)로 변환하는 과정입니다.
- [★☆☆] **청킹**(Chunking): 방대한 원본 문서를 검색과 임베딩 효율이 높은 적절한 크기의 작은 조각(Chunk)으로 분할하는 전처리 작업입니다.
- [★☆☆] **유사도 검색**(Similarity Search): 사용자 질문의 임베딩 벡터와 가장 의미가 가까운 문서 벡터를 벡터 DB에서 찾아내는 검색 기법입니다.
- [★☆☆] **벡터 데이터베이스**(Vector Database): 고차원 임베딩 벡터를 저장하고 빠르게 유사도 검색을 수행하는 전용 데이터베이스입니다. (예: Pinecone)
- [★☆☆] **Ollama**: 개인 PC나 로컬 서버 환경에서 오픈소스 LLM을 간편하게 설치·구동할 수 있는 로컬 LLM 실행 도구입니다.
- [★☆☆] **NVIDIA NIM**(`langchain-nvidia-ai-endpoints`): 클라우드 환경에서 다양한 오픈소스 파운데이션 모델을 최적화된 API 형태로 제공하는 엔터프라이즈 추론(Inference) 플랫폼입니다.
- [★☆☆] **구글 스티치**(Google Stitch): 프롬프트만으로 프로덕션 수준의 UI 화면과 디자인을 생성하는 구글의 AI 디자인 도구입니다.
- [★☆☆] **Claude Code**: 터미널 기반으로 동작하는 Anthropic의 에이전트형 AI 코딩 도구로, 프로젝트 내에서 비교·언급됩니다.
- [★☆☆] **Kiro**: 아마존 내부 AI 코딩 에이전트 도구로, 프로젝트 내에서 비교·언급됩니다.
- [★☆☆] **Genspark**: 프레젠테이션·콘텐츠 생성 등에 활용되는 AI 생성 플랫폼으로, 프로젝트 내에서 비교·언급됩니다.

## 3. 소프트웨어 아키텍처 · 개발 방법론 · 품질 관리

### 아키텍처 및 설계 원칙
- [★★★] **클린 아키텍처**(Clean Architecture): 비즈니스 핵심 로직과 외부 프레임워크·DB·UI를 계층별로 엄격히 분리하고 의존성 방향을 안쪽으로 고정하여, AI가 코드 구조를 쉽게 파악(가이드 정확도 향상)하고 유지보수성을 높이는 설계 원칙입니다.
- [★★☆] **SDD**(Spec-Driven Development, 명세 주도 개발): 코드 구현을 바로 지시하기 전에 요구사항, 설계 계획, 입출력 규격이 담긴 명세서(Spec)를 먼저 작성·승인하고, 이를 기준으로 AI 에이전트가 구현과 검증을 수행하도록 이끄는 개발 방법론입니다.
- [★★☆] **계층형 아키텍처**(Layered Architecture): 백엔드 시스템을 요청 수신(`Controller`), 비즈니스 로직(`Service`), 데이터 접근(`Repository`) 계층으로 분리하는 표준 구조입니다.
- [★★☆] **FSD**(Feature-Sliced Design): 프론트엔드 코드를 기능(Feature)과 계층(App, Pages, Widgets, Features, Entities, Shared) 단위로 수직·수평 분할하여 확장성과 결합도를 관리하는 아키텍처 방법론입니다.
- [★★☆] **풀스택**(Full-stack): 프론트엔드·백엔드·데이터베이스를 아우르는 소프트웨어 개발 전반을 모두 다루는 개발 역량 또는 형태입니다.
- [★★☆] **레거시 시스템**(Legacy System): 과거 기술이나 오래된 구조로 작성되어 유지보수와 AI 전환이 어려운 기존 소프트웨어 시스템입니다.
- [★★☆] **단일 진실 공급원**(SSOT, Single Source of Truth): 시스템 전반의 스키마, 디자인 토큰, 설정, 명세 등을 단 하나의 검증된 기준 원천으로 통합 관리하여 데이터 불일치와 AI의 환각·중복 구현을 방지하는 설계 원칙입니다.
- [★☆☆] **아토믹 디자인**(Atomic Design): UI를 원자(Atom), 분자(Molecule), 유기체(Organism), 템플릿, 페이지 단위로 쪼개어 컴포넌트 재사용성을 극대화하는 설계 방법론입니다.
- [★☆☆] **DTO**(Data Transfer Object): 계층 간 또는 클라이언트-서버 통신 시 필요한 데이터만 담아 주고받는 데이터 전송 전용 객체입니다.
- [★☆☆] **Entity**(엔티티): 데이터베이스의 테이블과 1:1로 직접 매핑되는 핵심 도메인 모델 객체입니다.
- [★☆☆] **상태 코로케이션**(State Colocation): 상태(State) 변수를 실제로 사용하는 가장 가까운 컴포넌트 범위 내에 배치하여 불필요한 리렌더링과 복잡도를 줄이는 원칙입니다.
- [★☆☆] **모노레포**(Monorepo): 프론트엔드, 백엔드 등 여러 프로젝트나 패키지를 하나의 단일 Git 저장소 안에서 통합 관리하는 구조입니다.

### 기획 및 개발 프로세스
- [★★★] **PRD**(Product Requirements Document, 요구사항 정의서): 만들고자 하는 서비스의 목적, 핵심 기능, 사용자 흐름, 제약 조건을 체계적으로 정리한 기획 문서입니다.
- [★★★] **MVP**(Minimum Viable Product, 최소 기능 제품): 핵심 가치만 담아 가장 빠르게 시장이나 사용자의 검증을 받기 위해 구현한 최소 단위의 제품입니다.
- [★★☆] **SDLC**(Software Development Life Cycle, 소프트웨어 개발 수명주기): 소프트웨어를 만들고 운영하는 전체 공정으로, 일반적으로 **요구사항 분석**(기획) → **설계** → **구현**(개발) → **테스트**(검증) → **배포** → **유지보수** 단계로 진행됩니다.
- [★★☆] **사용자 흐름**(User Flow): 사용자가 목표를 달성하기 위해 서비스 내 여러 화면을 이동하는 동선과 단계입니다.
- [★★☆] **와이어프레임**(Wireframe): 구체적인 디자인 요소를 입히기 전, 화면의 레이아웃과 정보 구조를 선과 상자로 개략적으로 그린 설계도입니다.
- [★★☆] **개념 증명**(PoC, Proof of Concept): 본격적인 제품(MVP) 개발이나 기술 도입에 앞서, 핵심 아이디어와 기술적 구현 가능성을 소규모 프로토타입으로 빠르게 검증하는 과정입니다.
- [★☆☆] **WBS**(Work Breakdown Structure): 프로젝트의 전체 목표를 세부 작업 단위로 분해하여 구조화한 작업 분할 체계입니다.
- [★☆☆] **보일러플레이트**(Boilerplate): 새 프로젝트를 시작할 때 반복적으로 필요한 기본 설정과 골격 코드 묶음입니다.

### 테스트 · 디버깅 · 코드 품질 관리
- [★★★] **TDD**(Test-Driven Development, 테스트 주도 개발): 구현 코드를 짜기 전에 실패하는 테스트 케이스를 먼저 작성하고, 이를 통과하도록 코드를 구현한 뒤 리팩토링하는 개발 방식입니다. AI 코딩에서는 AI에게 줄 가장 명확한 성공 기준(요구사항) 역할을 합니다.
- [★★★] **단위 테스트**(Unit Test): 개별 함수나 작은 모듈이 의도대로 동작하는지 독립적으로 검증하는 테스트입니다.
- [★★★] **리팩토링**(Refactoring): 외부 동작이나 기능은 그대로 유지하면서 내부 코드 구조의 가독성, 성능, 유지보수성을 개선하는 작업입니다.
- [★★★] **코드 리뷰**(Code Review): 작성된 코드의 버그, 보안 취약점, 아키텍처 준수 여부를 동료나 시니어 페르소나 AI가 점검하는 활동입니다.
- [★★★] **트러블슈팅**(Troubleshooting): 프로그램 실행 중 발생한 오류나 장애의 근본 원인을 추적·진단하여 정상 상태로 해결하는 문제 해결 과정입니다.
- [★★★] **검증 루프**(Verification Loop): 코드 수정 후 `git diff --stat` 확인이나 테스트 재실행 같은 자가 검증 절차를 반복하도록 강제하는 품질 통제 전략입니다.
- [★★★] **하드코딩**(Hardcoding): 변경될 수 있는 설정값이나 민감한 API 키 등을 외부 설정 파일(`.env`)로 분리하지 않고 소스 코드 내부에 직접 박아 넣는 나쁜 습관입니다.
- [★★☆] **통합 테스트**(Integration Test): 여러 모듈이나 계층(API, DB 등)을 함께 연동했을 때 정상 동작하는지 검증하는 테스트입니다.
- [★★☆] **E2E 테스트**(End-to-End Test): 실제 사용자 시나리오를 기준으로 화면(브라우저)부터 백엔드·DB까지 전체 흐름을 처음부터 끝까지 검증하는 테스트입니다.
- [★★☆] **클린 코드**(Clean Code): 다른 사람(그리고 AI)이 읽기 쉽고 이해하기 좋으며 중복 없이 명확하게 작성된 코드입니다.
- [★★☆] **정적 분석**(Static Analysis): 코드를 실행하지 않고 소스 코드 자체의 구조와 흐름을 분석해 잠재적 버그나 타입 오류를 찾아내는 과정입니다.
- [★★☆] **린팅**(Linting, ESLint): 코드 스타일 위반, 미사용 변수, 안티패턴 등을 자동 검사해 일관된 코드 품질을 유지해 주는 도구 및 작업입니다.
- [★★☆] **안티패턴**(Anti-pattern): 실제 문제 해결에 비효율적이거나 오히려 심각한 버그·유실을 초래하는 잘못된 구현 습관입니다.
- [★★☆] **엣지 케이스**(Edge Case): 극단적인 입력값이나 예외적인 상황에서만 발생하는 경계 조건의 문제입니다.
- [★★☆] **사이드 이펙트**(Side Effect): 코드 일부를 수정했을 때 의도치 않게 다른 기능이나 상태에 악영향을 미치는 현상입니다.
- [★★☆] **다층 방어 체계**(Defense in Depth): 도구 권한 제한, 자가 검증, 인간 최종 승인 등 여러 겹의 안전장치를 중복 배치해 사고를 막는 통제 전략입니다.
- [★★☆] **더미 데이터**(Dummy Data): 실제 개인정보 유출을 막고 개발·테스트를 진행하기 위해 실제 데이터 대신 새로 만들어 사용하는 가짜 데이터입니다.
- [★★☆] **데이터 마스킹**(Data Masking): 실제 존재하는 민감 정보(전화번호, 주민등록번호 등)의 일부를 `*` 등의 기호나 가명으로 가려 노출을 막는 보안 기법입니다.
- [★★☆] **의존성**(Dependency): 내 프로젝트가 동작하기 위해 가져다 쓰는 외부 라이브러리나 패키지 자체를 의미합니다.
- [★★☆] **패키지 매니저**(Package Manager): 프로젝트에 필요한 외부 라이브러리(의존성)를 설치·업데이트·버전 관리하는 도구입니다. (Node.js: `npm`, `npx`, `nvm` / Python: `pip`, `uv`, `pyproject.toml`, `requirements.txt`)

- [★★☆] **HTML5**: 웹 페이지의 뼈대와 콘텐츠 구조를 정의하는 웹 표준 마크업 언어입니다.

- [★☆☆] **SSR**(Server-Side Rendering): 웹 페이지를 브라우저가 아닌 서버에서 미리 렌더링해 완성된 HTML을 내려주는 렌더링 방식입니다.
- [★☆☆] **SPA**(Single Page Application): 초기 페이지 로드 후 전체 페이지를 새로고침하지 않고 필요한 데이터만 받아 화면을 동적으로 갱신하는 웹 앱 구조입니다.

- [★☆☆] **엠티 스테이트**(Empty State): 표시할 데이터가 아직 없을 때 빈 화면 대신 안내 문구와 행동을 제시하는 화면 상태입니다.

#### 브라우저 저장소 · 최적화 · 검색
- [★★☆] **페이지네이션**(Pagination): 대량의 목록 데이터를 페이지 번호 단위로 나누어 불러오는 UI 패턴입니다.
- [★★☆] **무한 스크롤**(Infinite Scroll): 사용자가 목록의 스크롤 끝에 도달할 때마다 다음 데이터를 자동으로 이어서 불러오는 UI 패턴입니다.
- [★★☆] **디바운스**(Debounce): 연속적으로 발생하는 이벤트(예: 검색어 입력, 자동 저장)가 일정 시간 멈췄을 때만 함수를 한 번 실행해 불필요한 호출과 부하를 줄이는 최적화 기법입니다.
- [★★☆] **로컬 스토리지**(Local Storage): 브라우저 내부에 키-값 형태로 데이터를 영구 저장해 새로고침 후에도 상태(예: 다크 모드 설정)를 유지하는 웹 저장소입니다.
- [★★☆] **웹 접근성**(a11y, Accessibility): 장애인이나 고령자 등 모든 사용자가 웹 서비스를 불편 없이 이용할 수 있도록 스크린 리더 지원, 키보드 탐색, 색상 대비 등을 보장하는 표준 설계 원칙입니다.
- [★★☆] **SEO**(Search Engine Optimization, 검색 엔진 최적화): 구글·네이버 등 검색 엔진 결과에서 웹사이트가 더 잘 노출되도록 메타 태그, 시맨틱 마크업, 사이트맵 등을 최적화하는 전략입니다.
- [★☆☆] **GEO**(Generative Engine Optimization, 생성형 엔진 최적화): ChatGPT·Perplexity·Gemini 같은 생성형 AI 검색 엔진이 내 웹사이트의 콘텐츠를 신뢰할 수 있는 출처로 인용·추천하도록 구조화된 데이터(JSON-LD)나 `llms.txt` 등으로 최적화하는 전략입니다.
- [★☆☆] **지연 로딩**(Lazy Loading): 초기 페이지 로딩 속도를 높이기 위해 이미지, 컴포넌트, 데이터 등을 당장 필요한 시점(예: 화면 스크롤에 진입할 때)에만 불러오는 최적화 기법입니다.
- [★☆☆] **헤드리스 브라우저**(Headless Browser): 그래픽 화면을 띄우지 않고 백그라운드에서 코드로 제어하며 웹 페이지를 렌더링·테스트·캡처하는 브라우저입니다.

## 5. 백엔드 · API · 데이터베이스 · 데스크톱 및 자동화

### 백엔드 프레임워크 및 API 통신
- [★★★] **클라이언트-서버 구조**(Client-Server Architecture): 사용자 화면을 담당하는 클라이언트(프론트엔드)와 비즈니스 로직·데이터 처리를 담당하는 서버(백엔드)가 네트워크로 통신하는 구조입니다.
- [★★★] **HTTP 메서드**(`GET`, `POST`, `PUT`, `DELETE`): 데이터 조회(`GET`), 생성(`POST`), 수정(`PUT`/`PATCH`), 삭제(`DELETE`) 등 요청 목적을 나타내는 HTTP 통신 방식입니다.
- [★★★] **JSON**(JavaScript Object Notation): 키-값 쌍으로 이루어진 웹·API 표준 경량 텍스트 데이터 형식입니다.
- [★★☆] **FastAPI**: 타입 힌트 기반으로 빠르고 간결하게 API 서버를 구축할 수 있는 고성능 Python 비동기 웹 프레임워크입니다.
- [★★☆] **REST API**(RESTful API): HTTP 메서드(`GET`, `POST`, `PUT`, `DELETE`)와 URI를 통해 자원을 주고받는 표준 웹 API 설계 방식입니다.
- [★★☆] **HTTP 상태 코드**(Status Code): 요청 처리 결과를 나타내는 3자리 숫자입니다. (`200 OK`, `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `500 Internal Server Error`)
- [★★☆] **HTTP 헤더**(Header): 요청·응답의 부가 정보를 담는 영역입니다. (`Authorization`: 인증 토큰, `Content-Type`: 데이터 형식)
- [★★☆] **엔드포인트**(Endpoint): API가 외부의 요청을 받아들이는 구체적인 URL 경로입니다.
- [★★☆] **페이로드**(Payload): API 요청이나 응답에 실어 보내는 실제 데이터 본문(Body)입니다.
- [★★☆] **미들웨어**(Middleware): 요청과 응답 사이에서 인증·CORS·로깅 등을 가로채 처리하는 중간 계층입니다.
- [★★☆] **CORS**(Cross-Origin Resource Sharing): 브라우저 보안 정책상 서로 다른 출처(도메인·포트) 간 리소스 요청을 허용할지 제어하는 HTTP 헤더 기반 메커니즘입니다.
- [★★☆] **CSV**(Comma-Separated Values): 쉼표(`,`)로 열을 구분해 표 형태의 데이터를 저장하는 텍스트 형식입니다.
- [★★☆] **Base64**: 이미지 등 바이너리 데이터를 ASCII 문자열로 변환해 텍스트 기반 환경에서 안전하게 전송하는 인코딩 방식입니다.
- [★★☆] **UTF-8**: 전 세계 모든 문자를 깨짐 없이 표현할 수 있는 표준 유니코드 문자 인코딩 방식입니다.
- [★☆☆] **Uvicorn**: FastAPI 등 Python 비동기 웹 애플리케이션(ASGI)을 실제로 구동해 요청을 처리하는 경량 웹 서버입니다.
- [★☆☆] **Pydantic**: Python 타입 어노테이션을 활용해 API 요청·응답 데이터의 형식과 유효성을 자동 검증·직렬화하는 라이브러리입니다.
- [★☆☆] **httpx**: 동기(`requests` 호환)와 비동기(`async/await`) 통신을 모두 지원하는 최신 Python HTTP 클라이언트 라이브러리입니다.
- [★☆☆] **Express**: Node.js 환경에서 가볍고 유연하게 웹 서버와 API를 구축하는 대표 프레임워크입니다.
- [★☆☆] **NestJS**: TypeScript 기반으로 체계적인 아키텍처를 지원하는 Node.js 백엔드 프레임워크입니다.
- [★☆☆] **Django**: 관리자 페이지와 ORM 등 다양한 웹 개발 기능을 기본 내장한 Python 풀스택 웹 프레임워크입니다.
- [★☆☆] **Flask**: 핵심 기능만 간결하게 제공해 가볍게 API 서버와 웹을 구축할 수 있는 Python 마이크로 웹 프레임워크입니다.
- [★☆☆] **Spring Boot**: Java 기반으로 엔터프라이즈 백엔드 웹 애플리케이션을 구축할 때 널리 쓰이는 프레임워크입니다.
- [★☆☆] **GraphQL**: 클라이언트가 필요한 데이터 필드와 구조만 선택해 요청할 수 있는 API 쿼리 언어입니다.
- [★☆☆] **프록시**(Proxy): 클라이언트와 서버 사이에서 요청을 대신 전달·중계하는 대리 서버입니다.

### 비동기 처리 · 네트워크 · 성능 최적화
- [★★☆] **비동기 처리**(Asynchronous Execution): 작업 완료를 기다리지 않고 다른 작업을 동시에 진행하는 방식입니다. (`async`/`await`, `Promise`, Python `asyncio`)
- [★★☆] **멀티스레딩**(Multithreading): 하나의 프로세스 안에서 여러 실행 흐름(스레드)을 동시에 돌려 GUI 창이 멈추지 않게 백그라운드 작업을 처리하는 기법입니다.
- [★★☆] **타임아웃**(Timeout): 응답 없는 요청을 무한정 기다리지 않도록 설정하는 최대 대기 시간 제한입니다.
- [★★☆] **재시도**(Retry): 일시적인 네트워크 오류가 발생했을 때 요청을 실패로 끝내지 않고 다시 시도(`retry-requests`)해 안정성을 확보하는 기법입니다.
- [★★☆] **캐싱**(Caching): 자주 조회되거나 최근에 받은 응답 데이터를 임시 저장(`requests-cache`)해 응답 속도를 높이고 서버 부하를 줄이는 기법입니다.
- [★☆☆] **데몬 스레드**(Daemon Thread): 메인 프로그램이 종료될 때 함께 자동 종료되도록 설정된 백그라운드 스레드입니다.
- [★☆☆] **콜백**(Callback): 특정 작업이 끝나거나 이벤트가 발생했을 때 호출되도록 넘겨주는 함수입니다.
- [★☆☆] **네트워크 왕복 시간**(Ping / RTT): 클라이언트가 서버에 요청을 보내고 응답이 돌아오기까지 걸리는 시간입니다.
- [★☆☆] **백오프**(Backoff): 재시도 시 서버 부하와 충돌을 줄이기 위해 요청 간 대기 간격을 점진적으로 늘려가며 대기하는 전략입니다.

### 데이터베이스 · BaaS · 서버리스
- [★★★] **데이터베이스**(Database): 회원 정보, 게시글, 주문 내역 같은 데이터를 체계적으로 영구 저장·관리하는 데이터 저장소입니다.
- [★★★] **스키마**(Schema): 데이터베이스 테이블의 구조, 열(Column)의 자료형, 제약조건 등을 정의한 청사진입니다.
- [★★☆] **SQL**(Structured Query Language): 관계형 데이터베이스에서 데이터를 조회·삽입·수정·삭제하기 위해 사용하는 표준 질의어입니다.
- [★★☆] **RDBMS**(관계형 데이터베이스): 정형화된 테이블과 행·열 구조로 데이터를 저장하고 테이블 간 관계를 관리하는 데이터베이스입니다. (예: PostgreSQL, SQLite)
- [★★☆] **ERD**(Entity-Relationship Diagram): 데이터베이스 테이블과 테이블 간의 관계(1:N, N:M 등)를 시각적으로 표현한 다이어그램입니다.
- [★★☆] **마이그레이션**(Migration): 데이터베이스 스키마의 변경 이력을 코드·파일로 버전 관리하며 안전하게 반영하는 작업입니다.
- [★★☆] **인덱싱**(Indexing): 대량의 데이터에서 특정 조건의 검색 속도를 빠르게 높이기 위해 별도의 색인(Index)을 생성하는 작업입니다.
- [★★☆] **CRUD**: 데이터 처리의 4가지 기본 기능인 생성(Create), 조회(Read), 수정(Update), 삭제(Delete)입니다.
- [★★☆] **트랜잭션**(Transaction, `@Transactional`): 여러 데이터베이스 작업을 하나의 논리적 단위로 묶어 전부 성공(Commit)하거나 하나라도 실패하면 전부 취소(Rollback)해 데이터 일관성을 보장하는 메커니즘입니다.
- [★★☆] **동시성 제어**(Concurrency Control / Locking): 여러 사용자가 동시에 같은 데이터를 수정할 때 충돌이나 데이터 훼손을 막기 위해 잠금(Lock) 등으로 접근 순서를 제어하는 기법입니다.
- [★★☆] **BaaS**(Backend-as-a-Service): 백엔드 서버를 직접 구축하지 않고도 데이터베이스, 회원 인증, 파일 저장소 등을 API 형태로 즉시 제공하는 클라우드 서비스 모델입니다.
- [★★☆] **Supabase**(수파베이스): PostgreSQL DB, 인증(Auth), 스토리지, 실시간 구독(Realtime) 기능을 통합 제공하는 대표적인 오픈소스 기반 BaaS 플랫폼입니다.
- [★★☆] **Google Apps Script**(GAS): 구글 워크스페이스(시트, 닥스 등)를 자동화할 수 있는 구글의 V8 런타임 기반 서버리스 실행 환경입니다.
- [★★☆] **Trigger**(트리거): Google Apps Script에서 시간 주기나 시트 편집 같은 특정 이벤트가 발생할 때 함수를 자동 실행하도록 연결하는 장치입니다.
- [★☆☆] **NoSQL**: 고정된 테이블 스키마 없이 문서, 키-값, 그래프 등 유연한 형태로 비정형·대용량 데이터를 저장하는 데이터베이스입니다.
- [★☆☆] **인메모리 키-값 저장소**(In-Memory Key-Value Store): 디스크 대신 메모리(RAM)에 데이터를 올려 초고속 캐시·세션 저장소로 사용하는 데이터베이스입니다. (예: Redis)
- [★☆☆] **ORM**(Object-Relational Mapping): 객체지향 코드(클래스/객체)와 관계형 데이터베이스 테이블을 자동으로 연결해 SQL 없이도 데이터를 다룰 수 있게 해주는 기술입니다.
- [★☆☆] **JPA**(Java Persistence API): 자바(Spring Boot) 진영에서 사용하는 표준 ORM 기술 명세입니다.
- [★☆☆] **N+1 문제**: ORM 사용 시 목록 1건을 조회하는 쿼리를 실행한 뒤 연관된 하위 데이터를 가져오기 위해 N번의 추가 쿼리가 발생해 성능이 저하되는 현상입니다.
- [★☆☆] **서버리스**(Serverless): 개발자가 서버 인프라를 직접 관리·운영하지 않고 작성한 코드만 업로드하면 요청 시 클라우드가 자동으로 실행해 주는 아키텍처입니다.
- [★☆☆] **Clasp CLI**: 로컬 환경에서 Google Apps Script 코드를 작성·관리하고 클라우드와 동기화할 수 있는 커맨드라인 도구입니다.

### 데스크톱 앱 · 파이썬 GUI 및 자동화 · 오픈 API
- [★★☆] **Tauri**: 웹 프론트엔드(HTML/JS/Next.js)와 Rust(`Cargo.toml`) 백엔드를 결합해 가벼운 네이티브 데스크톱 설치 파일(`.exe`, `.msi`)을 만드는 프레임워크입니다.
- [★★☆] **AppData**: OS가 각 애플리케이션의 설정이나 로컬 사용자 데이터를 저장하기 위해 할당하는 전용 앱 데이터 폴더입니다.
- [★★☆] **오픈 API**(Open API): 누구나 활용할 수 있도록 외부에 공개된 데이터·기능 인터페이스입니다. (예: 공공데이터포털, Open-Meteo, yfinance)
- [★☆☆] **Rust**: 메모리 안전성과 높은 성능을 보장하는 시스템 프로그래밍 언어로, Tauri v2의 네이티브 백엔드 구현에 사용됩니다.
- [★☆☆] **IPC**(Inter-Process Communication): Tauri에서 프론트엔드(웹뷰)와 Rust 네이티브 백엔드 사이에 파일 시스템(`plugin-fs`) 접근 등의 명령을 주고받는 프로세스 간 통신 방식입니다.
- [★☆☆] `asset://` **프로토콜**: Tauri 앱이 AppData 등 로컬 경로에 저장된 이미지 리소스를 보안 정책 범위 내에서 안전하게 불러오는 커스텀 프로토콜입니다.
- [★☆☆] **Tkinter**: 파이썬에 기본 내장되어 별도 설치 없이 바로 GUI 데스크톱 창을 만들 수 있는 표준 라이브러리입니다. (항상 위에 고정: `Topmost`)
- [★☆☆] **PyAutoGUI**: 파이썬 코드로 마우스 이동·클릭과 키보드 입력을 자동화하는 GUI 매크로 라이브러리입니다.
- [★☆☆] **키보드 후킹**(Keyboard Hooking): OS 수준에서 전역 키보드 입력 이벤트를 가로채 감지하고 단축키 동작 등을 수행하는 기법입니다.
- [★☆☆] **GIS**(Geographic Information System, 지리정보시스템): 위치·공간 데이터를 수집·분석하고 지도 위에 시각화하는 지리정보 처리 기술입니다. (예: 브이월드)
- [★☆☆] **지오코딩**(Geocoding): 지역명이나 주소를 위도·경도 좌표로 변환하는 지리정보 처리 기술입니다. (예: 브이월드, Nominatim)

## 6. 보안 · 인증 · 전자결제 · Git · 클라우드 배포

### 보안 및 인증
- [★★★] **인증**(Authentication): 사용자가 누구인지 신원을 확인하는 절차(로그인 등)입니다.
- [★★★] **인가**(Authorization): 인증된 사용자가 특정 리소스나 기능에 접근할 권한이 있는지 확인하는 절차입니다.
- [★★★] **환경 변수**(`.env`, `.env.example`): API 키, DB 비밀번호 등 민감한 설정값을 소스 코드와 분리해 보관·주입하는 변수 및 파일입니다.
- [★★★] **시크릿 키**(Secret Key): 절대 외부에 노출되면 안 되며 신뢰할 수 있는 백엔드 서버에서만 사용하는 비밀 키입니다.
- [★★☆] **OAuth 2.0**: 구글, 카카오 등 외부 플랫폼의 인증 체계를 안전하게 위임받아 소셜 로그인을 구현하는 개방형 표준 프로토콜입니다.
- [★★☆] **JWT**(JSON Web Token): 사용자 인증 정보와 서명을 JSON 객체에 담아 암호화해 주고받는 자기 수용적(Self-contained) 인증 토큰입니다.
- [★★☆] **RLS**(Row Level Security, 행 수준 보안): Supabase(PostgreSQL)에서 사용자가 본인의 데이터 행(Row)에만 접근·수정할 수 있도록 데이터베이스 엔진 차원에서 강제하는 보안 정책입니다.
- [★★☆] **SQL 인젝션**(SQL Injection): 입력창에 악의적인 SQL 쿼리를 삽입해 데이터베이스를 탈취·조작하는 보안 취약점입니다.
- [★★☆] **XSS**(Cross-Site Scripting): 웹 페이지에 악성 자바스크립트 코드를 삽입해 다른 사용자의 브라우저에서 실행되도록 하는 보안 취약점입니다.
- [★★☆] **자격 증명**(Credentials): 시스템이나 API에 접근하기 위해 필요한 인증 키, 비밀번호, 토큰 등의 접속 정보입니다.
- [★★☆] **클라이언트 키**(Client Key): 브라우저에 노출되어 SDK 초기화에 쓰이는 공개 키입니다.
- [★☆☆] **Basic Auth**: 사용자 ID와 비밀번호(또는 토스 시크릿 키 + `:`)를 Base64로 인코딩해 HTTP `Authorization` 헤더에 실어 보내는 인증 방식입니다.
- [★☆☆] **CSP**(Content Security Policy): 웹 페이지에서 허용되지 않은 외부 스크립트나 리소스 실행을 차단하는 브라우저 보안 헤더 정책입니다.
- [★☆☆] **X-Frame-Options**: 다른 웹사이트가 내 페이지를 `<iframe>`으로 삽입해 악용하는 클릭재킹 공격을 차단하는 HTTP 보안 헤더입니다.
- [★☆☆] **AES-256-GCM**: 데이터를 안전하게 암호화하고 무결성까지 검증하는 256비트 대칭키 암호화 알고리즘입니다.
- [★☆☆] **종단간 암호화**(End-to-End Encryption, E2EE): 데이터를 저장하거나 전송하기 전에 암호화하여 중간 서버나 DB 관리자조차 원문을 볼 수 없게 보호하는 기법입니다.
- [★☆☆] **접근 통제 목록**(ACL, Access Control List): 특정 데이터나 리소스에 대해 사용자·역할별로 읽기·쓰기·실행 등의 세부 권한을 목록으로 정의해 제어하는 보안 메커니즘입니다.
- [★☆☆] **감사 로그**(Audit Log): 누가, 언제, 어떤 데이터나 시스템 설정에 접근·변경했는지 추적과 사후 감사를 위해 시간순으로 기록하는 보안 전용 로그입니다.

### 전자결제 (Toss Payments 연동)
- [★★☆] **서버 신뢰 모델**(Server-Authoritative Model): 클라이언트(브라우저)는 결제 인증만 담당하고, 실제 결제 승인 요청과 유료 권한 부여는 반드시 신뢰할 수 있는 백엔드 서버에서 처리해야 하는 보안 원칙입니다.
- [★★☆] **금액 위변조 검증**(Amount Verification): 사용자가 브라우저에서 결제 금액을 임의로 조작해 인증하는 것을 막기 위해, 결제 승인 전 서버 DB에 사전 등록된 주문 금액과 대조하는 필수 검증 과정입니다.
- [★★☆] **빌링키**(Billing Key): 카드 정보를 등록해 발급받는 고유 키로, 매달 사용자의 개입 없이 정기 자동 결제를 청구할 때 사용합니다.
- [★★☆] **라우트 가드**(Route Guard): 로그인 여부나 유료 권한 등에 따라 특정 페이지 경로(Route) 진입을 사전에 허용·차단하는 접근 제어 패턴입니다.
- [★★☆] **웹훅**(Webhook): 가상계좌 입금 완료, 결제 상태 변경 등 외부 서버에서 발생한 이벤트를 내 백엔드 API URL로 실시간 푸시 알림해 주는 역방향 HTTP 콜백입니다.
- [★☆☆] **PG**(Payment Gateway): 온라인 결제를 중개하고 승인 처리를 대행하는 전자결제 서비스(토스페이먼츠 등)입니다.
- [★☆☆] **결제 SDK**(Software Development Kit): 프론트엔드 화면에 결제 위젯이나 결제창을 연동할 수 있도록 PG사가 제공하는 소프트웨어 개발 키트입니다.
- [★☆☆] **페이월**(Paywall): 유료 결제 사용자에게만 특정 콘텐츠나 기능 접근을 허용하고 미결제 시 결제 화면으로 유도하는 수익화 장벽입니다.

### Git 버전 관리 및 협업
- [★★★] **Git**: 소스 코드의 변경 이력을 로컬에서 추적·관리하는 분산 버전 관리 시스템입니다.
- [★★★] **GitHub**: Git 저장소를 클라우드에 호스팅하여 백업, 코드 리뷰, Pull Request 등 협업을 지원하는 플랫폼입니다.
#### 주요 Git 개념 및 명령어
- [★★★] `git commit`: 스테이징 영역의 변경 사항을 하나의 세이브포인트로 기록하는 명령어입니다.
- [★★★] **Pull Request**(PR): 수정한 브랜치나 Fork 저장소의 변경 사항을 원본 저장소에 병합해 달라고 요청하는 협업 흐름입니다.
- [★★★] `.gitignore`: `.env`, `node_modules/`, `.venv/` 등 Git 추적에서 제외할 파일·폴더 목록을 지정하는 설정 파일입니다.
- [★★☆] `git init`: 현재 디렉토리에서 새로운 Git 저장소를 초기화하는 명령어입니다.
- [★★☆] `git status`: 수정·추가된 파일과 스테이징 상태를 확인하는 명령어입니다.
- [★★☆] `git add`: 커밋할 변경 사항을 스테이징 영역에 담는 명령어입니다.
- [★★☆] `git log`: 저장소에 기록된 커밋 이력을 조회하는 명령어입니다.
- [★★☆] `git remote`: 로컬 저장소와 GitHub 등 원격 저장소를 연결·관리하는 명령어입니다.
- [★★☆] `git push`: 로컬 커밋 이력을 원격(클라우드) 저장소에 업로드하는 명령어입니다.
- [★★☆] `git pull`: 원격 저장소의 최신 변경 사항을 로컬로 내려받아 병합하는 명령어입니다.
- [★★☆] `git branch`: 기존 작업과 분리된 독립적인 작업 분기를 생성·조회하는 명령어입니다.
- [★★☆] `git restore`: 작업 트리의 수정 내용을 이전 커밋 상태로 되돌려 복구하는 명령어입니다.
- [★★☆] `git reset`: 브랜치의 현재 커밋 위치나 스테이징 상태를 이전 시점으로 되돌리는 명령어입니다.
- [★★☆] `git diff --stat`: 변경된 파일 목록과 추가·삭제된 라인 수 통계를 확인하는 명령어입니다.
- [★★☆] **커밋 컨벤션**(Commit Convention): `feat:`, `fix:`, `docs:`, `style:`, `refactor:`, `test:`, `chore:` 등 변경 목적을 표준화된 접두사로 명시하는 규칙입니다.
- [★☆☆] `git checkout`: 특정 브랜치나 커밋 시점으로 작업 트리를 전환하는 명령어입니다.
- [★☆☆] `git merge`: 다른 브랜치의 변경 사항을 현재 브랜치로 병합하는 명령어입니다.
- [★☆☆] `git worktree`: 하나의 저장소에서 여러 브랜치를 별도 폴더로 동시에 체크아웃해 작업할 수 있게 해주는 기능입니다.
- [★☆☆] `Fork`: 타인의 원격 저장소를 내 GitHub 계정으로 복제해 오는 기능입니다.

### 클라우드 인프라 · 배포 · 운영 모니터링
- [★★★] **배포**(Deploy): 내 컴퓨터에서만 실행되던 웹이나 프로그램을 클라우드 서버에 올려 누구나 인터넷 주소(URL)로 접속할 수 있게 공개하는 과정입니다.
- [★★★] **CI/CD**(Continuous Integration / Continuous Deployment): 코드 변경(`git push`) 시 자동으로 빌드·테스트·배포가 이루어지는 자동화 파이프라인입니다.
- [★★★] **롤백**(Rollback): 배포 후 문제가 발생했을 때 이전의 정상 동작 버전으로 즉시 되돌리는 복구 작업입니다.
- [★★☆] **SaaS**(Software as a Service): 별도 설치 없이 웹이나 클라우드를 통해 구독 형태로 바로 사용하는 완성형 소프트웨어 서비스입니다.
- [★☆☆] **무중단 배포**(Zero-downtime Deploy): 서비스가 멈추거나 사용자 연결이 끊기지 않게 새 버전을 교체·반영하는 배포 방식입니다.
- [★☆☆] **프리뷰 환경**(Preview Environment): PR(Pull Request)마다 실제 배포 전에 변경 사항을 미리 확인해 볼 수 있도록 자동으로 띄워주는 임시 테스트 URL 환경입니다.
- [★☆☆] **PaaS**(Platform as a Service): 서버 구축 없이 코드만 올리면 실행·확장해 주는 클라우드 애플리케이션 플랫폼입니다. (예: Render, Vercel, Heroku)
#### 주요 클라우드 호스팅 플랫폼
- [★★☆] **Vercel**: Next.js 등 프론트엔드·풀스택 웹 앱을 GitHub 연동으로 손쉽게 배포할 수 있는 클라우드 호스팅 플랫폼입니다.
- [★★☆] **Render**: 웹 서비스, 백그라운드 워커, 데이터베이스, 크론잡 등을 통합 호스팅할 수 있는 PaaS 클라우드 플랫폼입니다.
- [★★☆] **GitHub Pages**: GitHub 저장소의 정적 웹 파일(HTML/CSS/JS)을 무료로 웹 호스팅해 주는 서비스입니다.
- [★★☆] **CDN**(Content Delivery Network): 전 세계에 분산된 서버를 통해 이미지·CSS·JS 등 정적 파일을 사용자와 가장 가까운 위치에서 빠르게 전송하는 네트워크입니다.
- [★★☆] **SSL/TLS**: 웹 브라우저와 서버 간 통신 데이터를 암호화하여 도청·변조를 막는 보안 프로토콜(HTTPS의 기반)입니다.
- [★★☆] **크론잡**(Cron Job): 정해진 시간이나 주기마다 특정 스크립트·작업을 자동으로 반복 실행하는 스케줄러입니다.
- [★★☆] **로깅**(Logging): 시스템의 동작 이력, 사용자 요청, 오류 내용을 추적할 수 있도록 기록으로 남기는 작업입니다.
- [★★☆] **로그 수준**(Log Level): 로그의 중요도와 심각도를 구분하는 등급입니다. (`DEBUG`, `INFO`, `WARN`, `ERROR`)
- [★☆☆] **Cloudflare Pages**: 정적 웹사이트 및 JAMstack 앱을 글로벌 에지 네트워크를 통해 무료·고속으로 배포하는 호스팅 서비스입니다.
- [★☆☆] **Cloudflare Workers**: 전 세계 에지 서버에서 서버리스 JavaScript/TypeScript 코드를 실행하는 플랫폼입니다.
- [★☆☆] **AWS**(Amazon Web Services): 아마존이 제공하는 글로벌 클라우드 컴퓨팅 인프라 플랫폼입니다.
- [★☆☆] **GCP**(Google Cloud Platform): 구글이 제공하는 글로벌 클라우드 컴퓨팅 인프라 플랫폼입니다.
- [★☆☆] **애저**(Azure): 마이크로소프트(Microsoft)가 운영하는 글로벌 클라우드 컴퓨팅 플랫폼으로, AWS·GCP와 함께 대표적인 클라우드 인프라 서비스입니다.
- [★☆☆] **에지 캐싱**(Edge Caching): 사용자와 물리적으로 가까운 에지 서버에 응답이나 정적 자원을 미리 저장해 지연 시간을 줄이는 캐싱 기법입니다.
- [★☆☆] **에지 컴퓨팅**(Edge Computing): 데이터를 중앙 클라우드 서버까지 보내지 않고 사용자나 데이터 발생 지점과 가까운 에지 노드에서 즉시 처리해 응답 지연과 네트워크 부하를 줄이는 분산 처리 기술입니다.
- [★☆☆] **커스텀 도메인**(Custom Domain): 클라우드 플랫폼이 기본 제공하는 임시 주소 대신 직접 소유한 고유 도메인(`example.com`)을 연결해 사용하는 기능입니다.
- [★☆☆] **사설 네트워크**(Private Network): 외부 인터넷에 노출되지 않고 내부 서버·데이터베이스끼리만 안전하게 통신하는 격리된 네트워크 망입니다.
- [★☆☆] **IaC**(Infrastructure as a Code): `render.yaml`(Blueprints)이나 Terraform처럼 서버·DB·네트워크 구성을 코드 파일로 정의해 자동 프로비저닝하는 방식입니다.
- [★☆☆] **Docker**(도커): 애플리케이션과 실행 환경을 컨테이너 이미지로 패키징해 어디서나 동일하게 실행하는 가상화 기술입니다.
- [★☆☆] **백그라운드 워커**(Background Worker): 웹 요청 처리와 분리되어 큐에 쌓인 오래 걸리는 비동기 작업을 뒤에서 처리하는 전용 실행 인스턴스입니다.
- [★☆☆] **자동 스케일링**(Auto Scaling): 트래픽 증가나 부하에 따라 서버 자원(인스턴스 수·사양)을 자동으로 늘리거나 줄이는 기능입니다.
- [★☆☆] **자동 휴면**(Spin-down on idle): 일정 시간 요청이 없는 유휴 상태일 때 비용 절감을 위해 서버 인스턴스를 일시 정지시키는 기능입니다.
- [★☆☆] **콜드 스타트**(Cold Start): 휴면 상태였던 서버나 서버리스 함수가 첫 요청을 받아 깨어나며 초기 응답이 일시적으로 지연되는 현상입니다.
- [★☆☆] **헬스 체크**(Health Check): 서버가 정상적으로 살아있고 요청을 받을 수 있는지 주기적으로 상태를 확인하는 기능입니다.
- [★☆☆] **출력 리다이렉션**(Output Redirection): 대량의 터미널 실행 출력을 화면 대신 파일로 저장(`> test.log 2>&1`)해 컨텍스트 낭비를 막는 셸 기법입니다.
- [★☆☆] **GA4**(Google Analytics 4): 웹사이트·앱 사용자의 방문, 클릭, 전환 등 행동 데이터를 수집·분석하는 구글의 트래킹 도구입니다.
- [★☆☆] **벤더 락인**(Vendor Lock-in): 특정 클라우드, BaaS, AI 모델 공급업체의 독자 기능에 과도하게 의존하여 다른 플랫폼이나 모델로 이전하기 어려워지는 종속 현상입니다.

### 개발 환경 · 인터페이스 · 기초 도구
- [★★★] **터미널**(Terminal): 텍스트 명령어를 입력하고 실행 결과를 확인할 수 있는 명령줄 실행 창 프로그램입니다.
- [★★★] **CLI**(Command-Line Interface): 그래픽 대신 키보드로 텍스트 명령어를 입력해 컴퓨터나 도구를 제어하는 인터페이스입니다.
- [★★★] **IDE**(Integrated Development Environment): 코드 편집, 디버깅, 빌드, 터미널 실행 등을 한곳에서 지원하는 통합 개발 환경입니다. (예: VS Code, Antigravity)
- [★★☆] **GUI**(Graphical User Interface): 마우스와 창, 버튼, 아이콘 등 그래픽 요소를 통해 직관적으로 조작하는 사용자 인터페이스입니다.
- [★★☆] **정규표현식**(RegExp): 문자열에서 특정 패턴을 검색·추출·치환하기 위해 사용하는 형식 언어입니다. (탐욕적 Greedy vs 비탐욕적 Non-greedy 매칭)
- [★☆☆] **TUI**(Text-based User Interface): 터미널 창 안에서 텍스트와 키보드만으로 메뉴·화면을 조작할 수 있는 텍스트 기반 인터페이스입니다.
