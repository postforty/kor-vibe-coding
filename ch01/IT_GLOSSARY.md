## 1. AI · LLM · 바이브 코딩

### 핵심 패러다임 및 개념
- **바이브 코딩**(Vibe Coding): 개발자가 코드를 한 줄씩 직접 타이핑하는 대신, 자연어로 요구사항과 설계서(프롬프트)를 작성해 AI 에이전트에게 구현을 지시하고 결과물을 검증하는 설계자 중심의 개발 방식입니다. (안드레이 카파시가 처음 제시한 용어)
- **에이전틱 엔지니어링**(Agentic Engineering): 단순한 코드 생성 요청을 넘어, AI 에이전트에게 명세(Spec)와 테스트 케이스를 제공하고 계획·구현·검증·배포의 전체 소프트웨어 엔지니어링 수명주기를 지휘하는 개발 패러다임입니다.
- **에이전트 우선 아키텍처**(Agent-First Architecture): 사람(개발자)이 직접 코드를 편집하는 기존 IDE 중심 구조에서 벗어나, AI 에이전트가 주도적으로 작업 계획을 세우고 도구를 호출해 실행하는 개발 환경 구조입니다.
- **AX**(AI Transformation): 기업의 업무 프로세스와 개발 워크플로우 전반을 AI 중심으로 전환하여 생산성을 극대화하는 디지털 전환 전략입니다.

### 대규모 언어 모델(LLM) 원리 및 파라미터
- **LLM**(Large Language Model, 대규모 언어 모델): 방대한 텍스트 데이터를 학습하여 문맥을 이해하고 자연어 및 코드를 생성하는 거대 인공지능 모델입니다.
- **파운데이션 모델**(Foundation Model): 다양한 작업에 범용적으로 활용할 수 있도록 대규모 데이터로 사전 학습된 기반 AI 모델입니다. (예: Gemini, Claude, GPT, DeepSeek, Nemotron, Gemma, Llama)
- **다음 토큰 예측**(Next-Token Prediction): LLM이 입력된 문맥 뒤를 이을 가장 확률 높은 다음 단어(토큰)를 순차적으로 계산해 문장을 생성하는 핵심 동작 원리입니다.
- **토큰**(Token): LLM이 텍스트를 처리하고 과금하는 기본 단위(단어 또는 형태소 조각)입니다.
- **토큰 이코노미**(Token Economy): AI 모델별 특성과 비용을 이해하고 토큰을 전략적으로 투입해 개발 생산성과 비즈니스 부가가치를 극대화하는 사고방식 및 운영 전략입니다.
- **비결정론적 생성**(Non-deterministic / 확률적 생성): 동일한 프롬프트를 입력해도 매번 확률 계산(주사위 굴리기)에 의해 서로 다른 구조나 표현의 결과물이 생성되는 LLM의 특성입니다.
- **할루시네이션**(Hallucination, 환각): AI가 사실이 아니거나 존재하지 않는 라이브러리·API·정보를 확률적으로 그럴듯하게 지어내어 답변하는 현상입니다.
- **벤치마크**(Benchmark): AI 모델의 추론, 코딩, 수학 등 실제 성능을 객관적인 지표로 비교·평가하는 표준 시험입니다.
- **추론/사고 과정**(Reasoning / Thinking): 모델이 최종 답변을 내놓기 전에 내부적으로 논리적 단계를 밟아 생각하는 과정입니다. (`enable_thinking`, `reasoning_content`)
- **샘플링 파라미터**(`temperature`, `top_p`): 모델이 다음 토큰을 선택할 때의 무작위성과 다양성을 조절하는 하이퍼파라미터입니다.
- `max_completion_tokens`: AI 모델이 한 번의 응답에서 생성할 수 있는 최대 토큰 수를 제한하는 설정입니다.
- **스트리밍**(Streaming): AI가 전체 답변을 완성할 때까지 기다리지 않고, 생성되는 토큰 조각(Chunk)을 실시간으로 순차 출력하는 전송 방식입니다.

### 프롬프트 엔지니어링 및 컨텍스트 관리
- **프롬프트**(Prompt): AI 모델에게 작업을 지시하거나 질문을 던지는 자연어 입력문입니다.
- **프롬프트 엔지니어링**(Prompt Engineering): AI로부터 원하는 정확하고 일관된 결과물을 얻기 위해 입력 문장의 구조, 제약, 예시를 정교하게 설계하는 기술입니다.
- **시스템 프롬프트**(System Prompt / System Instructions): 대화 전반에 걸쳐 AI의 역할, 어조, 행동 규칙, 제약 조건을 최우선으로 규정하는 배경 지시문입니다.
- **페르소나 프롬프팅**(Persona Prompting): AI에게 특정 전문가(예: 시니어 코드 리뷰어, 사서, 보안 감사자)의 역할을 부여해 답변의 관점과 전문성을 높이는 기법입니다.
- **제로샷 프롬프팅**(Zero-shot Prompting): 별도의 입출력 예시 없이 바로 질문이나 지시만 전달해 답변을 유도하는 방식입니다.
- **퓨샷 프롬프팅**(Few-shot Prompting): AI가 원하는 패턴과 출력 형식을 학습할 수 있도록 프롬프트 안에 몇 가지 입출력 예시를 함께 제시하는 기법입니다.
- **사고의 사슬**(CoT, Chain of Thought): AI가 성급하게 결론이나 코드를 내놓지 않고 "원인 분석 → 부작용 검토 → 해결 코드"처럼 단계별 논리 과정을 거쳐 답하도록 유도하는 기법입니다.
- **계획 우선 설계**(Plan-First): 코드 구현을 바로 지시하지 않고 작업 계획서 작성과 승인 단계를 먼저 거쳐 논리적 오류를 방지하는 작업 분할 전략입니다.
- **Step-Back / Self-Consistency**: 과거 모델의 추론 한계를 보완하기 위해 원리부터 설명하게 하거나 다수결 투표를 유도하던 고전 프롬프팅 기법입니다.
- **TCREI 프레임워크**: 구글에서 제안하는 프롬프트 작성 표준 구조로 **Task**(작업), **Context**(맥락), **Reference**(참조), **Evaluate**(평가), **Iterate**(반복)의 약자입니다. (`RTF` 등 유사 프레임워크 포함)
- **네거티브 제약**(Negative Constraints): "코드 생략 금지", "임의 패키지 설치 금지" 등 AI가 절대 하지 말아야 할 행동을 명확히 금지하는 프롬프트 규칙입니다.
- **구조화된 출력**(Structured Output): 인사말이나 마크다운 기호 없이 API나 프로그램이 바로 파싱할 수 있는 순수 JSON 등 고정된 스키마 형태로만 출력을 강제하는 기법입니다.
- **컨텍스트 윈도우**(Context Window): AI 모델이 한 번의 대화 세션에서 기억하고 동시에 처리할 수 있는 입력·출력 텍스트의 최대 용량입니다.
- **컨텍스트 격리**(Context Isolation): 메인 작업 세션의 대화 기록을 오염시키지 않기 위해, 탐색이나 리서치 작업을 별도의 깨끗한 세션(서브에이전트 등)으로 분리하는 전략입니다.
- **컨텍스트 오염/비대화**(Context Bloat / Context Window Pollution): 불필요한 로그, 파일 전문, 긴 대화 내역이 컨텍스트 윈도우에 누적되어 AI의 집중도와 응답 품질이 떨어지는 현상입니다.
- **프롬프트 인젝션**(Prompt Injection): 외부 문서, 웹사이트, 검증되지 않은 스킬 파일 등에 악의적인 명령을 숨겨두어 AI 에이전트가 원래 의도와 다른 위험한 동작(예: `.env` 탈취)을 하도록 유도하는 보안 공격입니다.

## 2. AI 에이전트 · 오케스트레이션 · Antigravity 생태계

### 에이전트 아키텍처 및 제어
- **AI 에이전트**(AI Agent): 단순 질의응답을 넘어 스스로 목표를 계획하고, 파일 읽기/쓰기·터미널 실행·웹 검색 등의 도구를 호출해 자율적으로 과업을 수행하는 AI 시스템입니다.
- **에이전트 하네스**(Agent Harness): AI 모델(두뇌)을 감싸 실제 작업 환경과 연결하고, 규칙·도구·워크플로우·메모리를 제어하는 실행 프레임워크입니다. ($\text{Agent} = \text{Model} + \text{Harness}$)
- **에이전트 오케스트레이션**(Agent Orchestration): 한 명의 설계자가 여러 역할의 AI 에이전트(기획, 프론트엔드, 백엔드, QA 등)에게 동시에 작업을 분배하고 조율·관리하는 기법입니다.
- **서브에이전트**(Subagent): 메인 에이전트의 컨텍스트를 보존하고 복잡한 작업을 병렬로 처리하기 위해 백그라운드의 독립된 깨끗한 세션(Clean Slate)에서 비동기로 실행되는 자식 에이전트입니다.
- **내장 서브에이전트**(Built-in Subagent): Antigravity에 기본 탑재된 전담 에이전트입니다. (`research`: 코드베이스 탐색, `browser`: 브라우저 제어 및 테스트, `self`: 메인 에이전트 복제)
- **커스텀 서브에이전트**(Custom Subagent): 사용자가 `.agents/agents/*.md` 경로에 YAML Frontmatter와 시스템 프롬프트를 작성해 직접 정의하는 역할별 전문 에이전트입니다.
- **중첩 깊이 제한**(Nesting Depth Limit): 서브에이전트가 또 다른 서브에이전트를 연쇄 호출할 수 있는 최대 단계 제한입니다. (Antigravity 기준 최대 10단계)
- **자동 깨어남**(Auto-Wake): 작업을 마치고 유휴(Idle) 상태로 대기 중인 서브에이전트가 Conversation ID 기반 메시지를 수신하면 즉시 실행(Running) 상태로 재개되는 메커니즘입니다.
- **에이전트 간 통신**(Inter-Agent Communication): 에이전트들이 고유 대화 식별자(Conversation ID)를 통해 서로 지시나 결과를 주고받는 구조입니다.
- **헤드리스 에이전트**(Headless Agent): 그래픽 화면(UI) 없이 CLI나 Python SDK 스크립트를 통해 백그라운드에서 프로그래밍 방식으로 실행되는 에이전트입니다.
- **멀티턴 세션**(Multi-turn Session): 이전 대화의 맥락을 세션별로 저장·조회하며 연속적으로 대화를 이어가는 방식입니다.
- **속도 편향**(Speed Bias): AI 에이전트가 안전 가이드라인을 인지하고도 작업을 빨리 끝내려는 경향 때문에 위험한 지름길(예: 대형 파일 정규식 일괄 치환)을 선택하는 현상입니다.
- **소프트 가드레일**(Soft Guardrail): 자연어로 작성된 규칙이나 프롬프트 지침을 뜻하며, 에이전트의 오작동을 물리적으로 100% 차단하지는 못하는 한계를 지닙니다.

### 도구 연동 · 규격 · Antigravity 기능
- **툴 콜링**(Tool Calling / 도구 바인딩): LLM이 외부 함수, API, 데이터베이스, 시계, 터미널 등 실제 도구를 직접 호출하고 그 실행 결과를 받아 답변에 반영하는 기능입니다.
- **MCP**(Model Context Protocol): AI 모델이 외부 데이터 소스, 데이터베이스(Supabase), 결제 시스템(토스페이먼츠), 문서(Context7) 등과 표준화된 방식으로 통신할 수 있도록 연결하는 개방형 프로토콜입니다.
- `AGENTS.md` / `CLAUDE.md`: 프로젝트 루트에 위치하여 AI 에이전트가 프로젝트 전반에서 준수해야 할 전역 행동 지침, 보안 제약, 아키텍처 규칙을 선언하는 표준 문서입니다.
- **규칙**(Rules): `.agents/rules/*.md` 등에 저장되어 매 대화 턴마다 컨텍스트에 상시 자동 포함되는 프로젝트의 고정 원칙과 금지 사항입니다.
- **워크플로우**(Workflows): `.agents/workflows/*.md`에 정의해 두고, 사용자가 `/커맨드명` 형태로 호출할 때만 온디맨드로 로드되는 절차적 작업 매뉴얼입니다.
- **슬래시 커맨드**(Slash Command): 채팅창에 `/`로 시작하는 명령어를 입력해 특정 워크플로우나 에이전트 기능을 즉시 실행하는 단축 명령입니다. (예: `/commit`, `/tdd`, `/grill-me`, `/research`, `/teamwork`, `/browser`, `/agents`)
- **에이전트 스킬**(Agent Skills / `SKILL.md`): 특정 작업에 대한 지침, 모범 사례, 실행 스크립트(`scripts/`), 리소스(`resources/`)를 폴더 단위로 패키징한 재사용 가능한 지식 모듈입니다.
- **점진적 공개**(Progressive Disclosure): 에이전트가 대화 시작 시 모든 스킬의 본문을 읽지 않고 이름·설명만 확인(Discovery)한 뒤, 필요할 때만 전체 `SKILL.md`를 읽어(Activation) 실행하는 토큰 절약 패턴입니다.
- **아티팩트**(Artifact): Antigravity 에이전트가 작업 과정과 결과를 체계적으로 브리핑하기 위해 생성하는 마크다운 보고서, 구현 계획서, 작업 목록, 브라우저 녹화 영상 등의 산출물입니다.
- **플러그인**(Plugin) & **생명주기 훅**(Lifecycle Hook): 스킬·에이전트·규칙·MCP 서버를 하나로 묶어 설치·관리하는 확장 번들과, 에이전트 동작의 특정 시점에 개입하는 훅 메커니즘입니다.
- **에디터 뷰**(Editor View) vs **매니저 뷰**(Manager View): Antigravity에서 코드를 직접 보고 편집하는 화면(에디터 뷰)과 여러 AI 에이전트를 동시에 지휘·모니터링하는 오케스트레이션 화면(매니저 뷰)입니다.
- **인라인 에디트**(Inline Edit, `Ctrl + I`): 사이드바 메인 채팅창의 컨텍스트를 소모하지 않고 에디터 내 특정 코드 블록만 선택해 즉석에서 수정하는 경량 편집 기능입니다.
- **Antigravity CLI**(`agy`) & **Python SDK**(`google-antigravity`): 터미널 명령어 또는 파이썬 스크립트로 Antigravity 에이전트를 제어하고 자동화 파이프라인을 구축할 수 있는 인터페이스입니다.

### RAG · 벡터 DB · AI 프레임워크 및 생태계 도구
- **RAG**(Retrieval-Augmented Generation, 검색 증강 생성): LLM이 학습하지 않은 최신 정보나 사내·개인 지식 베이스를 외부 데이터베이스에서 먼저 검색한 뒤, 그 근거를 바탕으로 답변을 생성하는 파이프라인 기술입니다.
- **임베딩**(Embedding): 텍스트나 문서의 의미를 AI가 수학적 거리(유사도)로 계산할 수 있도록 고차원 숫자 벡터(배열)로 변환하는 과정입니다.
- **청킹**(Chunking): 방대한 원본 문서를 검색과 임베딩 효율이 높은 적절한 크기의 작은 조각(Chunk)으로 분할하는 전처리 작업입니다.
- **유사도 검색**(Similarity Search): 사용자 질문의 임베딩 벡터와 가장 의미가 가까운 문서 벡터를 벡터 DB에서 찾아내는 검색 기법입니다.
- **벡터 데이터베이스**(Vector Database): 고차원 임베딩 벡터를 저장하고 빠르게 유사도 검색을 수행하는 전용 데이터베이스입니다. (예: Pinecone)
- **랭체인**(LangChain): LLM과 외부 데이터, 프롬프트 템플릿, 체인(Chain), 리트리버(Retriever), 출력 파서(Output Parser), 에이전트를 연결해 AI 애플리케이션을 구축하는 프레임워크입니다.
- **멀티 벤더**(Multi-vendor) & **모델 스위칭**(Model Switching): 작업 난이도와 비용(토큰 이코노미)에 따라 Gemini Flash/Pro, Claude, GPT, NVIDIA NIM, Ollama 등 여러 공급자의 AI 모델을 유연하게 교체·혼용하는 전략입니다.
- **로컬 LLM & 엔터프라이즈 추론 플랫폼**: 개인 PC에서 로컬로 LLM을 구동하는 **Ollama**와, 클라우드에서 다양한 오픈소스 파운데이션 모델을 API로 제공하는 **NVIDIA NIM** (`langchain-nvidia-ai-endpoints`)이 있습니다.
- **구글 스티치**(Google Stitch): 프롬프트만으로 프로덕션 수준의 UI 화면과 디자인을 생성하는 구글의 AI 디자인 도구입니다.
- **기타 AI 코딩/생성 도구**: Cursor, Claude Code, Kiro(아마존 내부 AI 코딩 에이전트), Genspark 등이 프로젝트 내에서 비교·언급됩니다.

## 3. 소프트웨어 아키텍처 · 개발 방법론 · 품질 관리

### 아키텍처 및 설계 원칙
- **클린 아키텍처**(Clean Architecture): 비즈니스 핵심 로직과 외부 프레임워크·DB·UI를 계층별로 엄격히 분리하고 의존성 방향을 안쪽으로 고정하여, AI가 코드 구조를 쉽게 파악(가이드 정확도 향상)하고 유지보수성을 높이는 설계 원칙입니다.
- **계층형 아키텍처**(Layered Architecture): 백엔드 시스템을 요청 수신(`Controller`), 비즈니스 로직(`Service`), 데이터 접근(`Repository`) 계층으로 분리하는 표준 구조입니다.
- **FSD**(Feature-Sliced Design): 프론트엔드 코드를 기능(Feature)과 계층(App, Pages, Widgets, Features, Entities, Shared) 단위로 수직·수평 분할하여 확장성과 결합도를 관리하는 아키텍처 방법론입니다.
- **아토믹 디자인**(Atomic Design): UI를 원자(Atom), 분자(Molecule), 유기체(Organism), 템플릿, 페이지 단위로 쪼개어 컴포넌트 재사용성을 극대화하는 설계 방법론입니다.
- **DTO**(Data Transfer Object) & **Entity**(엔티티): 데이터베이스 테이블과 직접 매핑되는 내부 객체(Entity)와 계층 간·클라이언트 통신에 사용하는 데이터 전송 객체(DTO)를 분리해 보안과 결합도를 관리하는 패턴입니다.
- **상태 코로케이션**(State Colocation): 상태(State) 변수를 실제로 사용하는 가장 가까운 컴포넌트 범위 내에 배치하여 불필요한 리렌더링과 복잡도를 줄이는 원칙입니다.
- **모노레포**(Monorepo): 프론트엔드, 백엔드 등 여러 프로젝트나 패키지를 하나의 단일 Git 저장소 안에서 통합 관리하는 구조입니다.
- **풀스택**(Full-stack): 프론트엔드·백엔드·데이터베이스를 아우르는 소프트웨어 개발 전반을 모두 다루는 개발 역량 또는 형태입니다.
- **레거시 시스템**(Legacy System): 과거 기술이나 오래된 구조로 작성되어 유지보수와 AI 전환이 어려운 기존 소프트웨어 시스템입니다.

### 기획 및 개발 프로세스
- **PRD**(Product Requirements Document, 요구사항 정의서): 만들고자 하는 서비스의 목적, 핵심 기능, 사용자 흐름, 제약 조건을 체계적으로 정리한 기획 문서입니다.
- **명세서**(Spec / Specification): 시스템이 충족해야 할 기술적 요구사항과 입출력 규격을 정의한 문서입니다.
- **WBS**(Work Breakdown Structure): 프로젝트의 전체 목표를 세부 작업 단위로 분해하여 구조화한 작업 분할 체계입니다.
- **사용자 스토리**(User Story) & **사용자 흐름**(User Flow): 사용자의 관점에서 기능을 정의한 서술("누구로서 무엇을 원한다")과 사용자가 서비스 내에서 이동하는 동선입니다.
- **와이어프레임**(Wireframe): 구체적인 디자인 요소를 입히기 전, 화면의 레이아웃과 정보 구조를 선과 상자로 개략적으로 그린 설계도입니다.
- **MVP**(Minimum Viable Product, 최소 기능 제품): 핵심 가치만 담아 가장 빠르게 시장이나 사용자의 검증을 받기 위해 구현한 최소 단위의 제품입니다.
- **보일러플레이트**(Boilerplate): 새 프로젝트를 시작할 때 반복적으로 필요한 기본 설정과 골격 코드 묶음입니다.

### 테스트 · 디버깅 · 코드 품질 관리
- **TDD**(Test-Driven Development, 테스트 주도 개발): 구현 코드를 짜기 전에 실패하는 테스트 케이스를 먼저 작성하고, 이를 통과하도록 코드를 구현한 뒤 리팩토링하는 개발 방식입니다. AI 코딩에서는 AI에게 줄 가장 명확한 성공 기준(요구사항) 역할을 합니다.
- **단위 테스트**(Unit Test), **통합 테스트**(Integration Test), **E2E 테스트**(End-to-End Test): 개별 함수/모듈 검증(단위), 모듈 간 연동 검증(통합), 실제 사용자 시나리오 기준 처음부터 끝까지의 전체 흐름 검증(E2E)을 의미합니다.
- **리팩토링**(Refactoring): 외부 동작이나 기능은 그대로 유지하면서 내부 코드 구조의 가독성, 성능, 유지보수성을 개선하는 작업입니다.
- **클린 코드**(Clean Code): 다른 사람(그리고 AI)이 읽기 쉽고 이해하기 좋으며 중복 없이 명확하게 작성된 코드입니다.
- **정적 분석**(Static Analysis) & **린팅**(Linting, ESLint): 코드를 실행하지 않고 소스 코드 자체를 분석해 문법 오류, 스타일 위반, 잠재적 버그를 찾아내는 과정입니다.
- **코드 리뷰**(Code Review): 작성된 코드의 버그, 보안 취약점, 아키텍처 준수 여부를 동료나 시니어 페르소나 AI가 점검하는 활동입니다.
- **포스트모텀**(Postmortem) & **근본 원인 분석**(Root Cause Analysis): 장애나 사고가 발생한 뒤 원인을 깊이 분석하고 재발 방지 대책을 기록하는 사후 회고 문서입니다.
- **안티패턴**(Anti-pattern): 실제 문제 해결에 비효율적이거나 오히려 심각한 버그·유실을 초래하는 잘못된 구현 습관입니다.
- **엣지 케이스**(Edge Case): 극단적인 입력값이나 예외적인 상황에서만 발생하는 경계 조건의 문제입니다.
- **부작용**(Side Effect): 코드 일부를 수정했을 때 의도치 않게 다른 기능이나 상태에 악영향을 미치는 현상입니다.
- **외과수술적 변경**(Surgical Changes): 요청받은 핵심 부분만 최소한으로 정밀하게 수정하고 주변의 정상 코드를 건드리지 않는 편집 원칙입니다.
- **검증 루프**(Verification Loop) & **다층 방어 체계**(Defense in Depth): 코드 수정 후 `git diff --stat` 등 자가 검증을 강제하고, 도구 제한·자가 검증·인간 승인 등 여러 겹의 안전장치를 두는 통제 전략입니다.
- **하드코딩**(Hardcoding): 변경될 수 있는 설정값이나 민감한 API 키 등을 외부 설정 파일(`.env`)로 분리하지 않고 소스 코드 내부에 직접 박아 넣는 나쁜 습관입니다.
- **더미 데이터**(Dummy Data) & **데이터 마스킹**(Data Masking): 실제 개인정보 유출을 막기 위해 실제 데이터 대신 사용하는 가짜 테스트 데이터와, 민감 정보를 가명·기호로 가리는 기법입니다.
- **패키지 매니저**(Package Manager) & **의존성**(Dependency): 프로젝트가 사용하는 외부 라이브러리(의존성)를 설치·버전 관리하는 도구입니다. (Node.js: `npm`, `npx`, `nvm` / Python: `pip`, `uv`, `pyproject.toml`, `requirements.txt`)

## 4. 웹 프론트엔드 · UI/UX · 디자인 시스템

### 웹 기초 및 프레임워크
- **HTML5 / CSS3 / JavaScript**: 웹 페이지의 구조(HTML), 스타일(CSS), 동적 동작(JS)을 담당하는 웹 표준 3대 핵심 기술입니다. (프레임워크 없이 순수하게 쓰는 것을 Vanilla CSS, Vanilla JS라고 부릅니다.)
- **DOM**(Document Object Model): HTML 문서를 자바스크립트가 탐색하고 조작할 수 있도록 트리 형태의 객체로 표현한 모델입니다.
- **Canvas 2D API**: HTML `<canvas>` 요소 위에 자바스크립트로 2D 그래픽(예: 테트리스 게임 블록)을 직접 그리는 브라우저 API입니다.
- **TypeScript**(`tsconfig.json`): 자바스크립트에 정적 타입(Type Safety)을 추가하여 컴파일 단계에서 오류를 사전에 잡아내는 프로그래밍 언어입니다.
- **React**: 컴포넌트 기반으로 사용자 인터페이스를 구축하는 대표적인 자바스크립트 UI 라이브러리입니다.
- **Next.js**: React 기반의 풀스택 웹 프레임워크로, 본 프로젝트에서는 **App Router** 라우팅, **SSR**(Server-Side Rendering) 제어, 그리고 Tauri 데스크톱 앱 패키징을 위한 **Static Export**(`output: 'export'`) 기능이 활용됩니다.
- **Vite**: 빠른 개발 서버 구동과 번들링을 제공하는 최신 프론트엔드 빌드 도구입니다.
- **SPA**(Single Page Application): 초기 페이지 로드 후 전체 페이지를 새로고침하지 않고 필요한 데이터만 받아 화면을 동적으로 갱신하는 웹 앱 구조입니다.

### 스타일링 · 에디터 · 문서화 도구
- **Tailwind CSS** & **PostCSS**: HTML 클래스명만으로 빠르게 스타일을 조합하는 유틸리티 우선(Utility-first) CSS 프레임워크와 CSS 변환 도구입니다.
- **Shadcn UI** / **Radix UI** / **Base UI** / **Mantine**: 접근성이 보장된 헤드리스 UI 프리미티브를 기반으로 커스터마이징이 자유로운 모던 React UI 컴포넌트 라이브러리들입니다.
- **BlockNote** / **Tiptap**: 노션(Notion)처럼 슬래시(`/`) 커맨드와 블록 단위 편집을 지원하는 React 기반 리치 텍스트 에디터 엔진입니다.
- **WYSIWYG**(What You See Is What You Get): 마크다운 문법 등을 입력하는 즉시 최종 렌더링된 화면 형태로 보며 편집하는 방식입니다.
- **마크다운**(Markdown, **GFM**): 텍스트 기반의 경량 마크업 언어로, GitHub Flavored Markdown(표, 체크리스트 등 확장 문법)이 널리 쓰입니다.
- **YAML Frontmatter**: 마크다운 문서 최상단에 `---`로 감싸 작성하는 메타데이터 블록입니다. (스킬, 에이전트, Marp 설정 등에 사용)
- **문서·발표 시각화 도구**:
  - **Mermaid**: 텍스트 코드로 순서도, 시퀀스 다이어그램 등을 그리는 도구
  - **draw.io**(diagrams.net): 웹 기반 다이어그램 드로잉 도구
  - **Marp**: 마크다운 파일을 슬라이드(PDF/HTML/PPTX)로 변환하는 도구 (Directive 지시어 활용)
  - **reveal.js**: HTML 기반의 웹 프레젠테이션 프레임워크
  - **Pandoc**: 다양한 문서 포맷 간 상호 변환을 수행하는 CLI 도구
  - **Puppeteer** & **PptxGenJS**: 헤드리스 크롬 브라우저로 HTML 슬라이드를 고해상도 캡처해 파워포인트(`.pptx`)로 변환하는 파이프라인 도구

### UI/UX · 디자인 시스템 · 브라우저 API
- **반응형 디자인**(Responsive Design) & **브레이크포인트**(Breakpoint): 모바일·태블릿·데스크톱 등 화면 크기(해상도 기준점)에 따라 레이아웃이 유동적으로 변하는 웹 설계 방식입니다.
- **디자인 시스템**(Design System) & **디자인 토큰**(Design Token): 서비스 전반의 일관된 UI/UX를 위해 색상, 타이포그래피, 여백, 그림자, 컴포넌트 규격을 변수(토큰)로 체계화한 문서(`DESIGN.md`) 및 규격입니다.
- **디자인 세부 용어**: **가변 폰트**(Variable Font), **엘리베이션**(Elevation, 그림자 깊이 단계), **스크림**(Scrim, 모달 뒤 어두운 반투명 배경), **히어로 섹션**(Hero Section, 첫 화면 대표 영역), **CTA**(Call-To-Action, 핵심 행동 유도 버튼), **캐러셀**(Carousel, 이미지 슬라이더), **모달**(Modal, 팝업 창), **토스트 메시지**(Toast, 일시적 알림 배너), **스켈레톤 스크린**(Skeleton Screen, 로딩 중 뼈대 화면).
- **페이지네이션**(Pagination) & **무한 스크롤**(Infinite Scroll): 대량의 목록 데이터를 페이지 번호로 나누거나 스크롤 끝에 도달할 때마다 자동으로 이어서 불러오는 UI 패턴입니다.
- **디바운스**(Debounce) & **자동 저장**(Autosave): 연속적으로 발생하는 이벤트(예: 타이핑)가 일정 시간(예: 400ms) 멈췄을 때만 최종 저장 함수를 한 번 실행해 부하를 줄이는 최적화 기법입니다.
- **로컬 스토리지**(Local Storage): 브라우저 내부에 키-값 형태로 데이터를 영구 저장해 새로고침 후에도 상태(예: 다크 모드 설정)를 유지하는 웹 저장소입니다.
- **Web Audio API**: 브라우저에서 별도 오디오 파일이나 외부 플레이어 없이 자바스크립트로 알림음 등 소리를 합성·재생하는 API입니다.
- **FileReader API**: 웹 브라우저에서 사용자가 선택한 이미지 등 로컬 파일을 비동기로 읽어 Base64 문자열 등으로 변환하는 API입니다.
- **웹 접근성**(a11y, Accessibility) & **WCAG**: 장애인이나 고령자 등 모든 사용자가 웹 서비스를 불편 없이 이용할 수 있도록 보장하는 표준 지침입니다. (**터치 타겟**: 모바일에서 손가락으로 누르기 적당한 최소 버튼 크기)
- **SEO**(검색 엔진 최적화), **메타 태그**(Meta Tag), **OG 태그**(Open Graph Tag): 검색 엔진 노출을 높이고, 카카오톡·슬랙 등에 URL을 공유할 때 제목·설명·썸네일 미리보기 카드가 표시되도록 `<head>`에 작성하는 태그입니다.
- **코드 스플리팅**(Code Splitting) & **지연 로딩**(Lazy Loading, `loading="lazy"`): 초기 로딩 속도를 높이기 위해 코드를 필요한 조각으로 나누거나 화면에 보일 때 이미지·컴포넌트를 불러오는 최적화 기법입니다.
- **헤드리스 브라우저**(Headless Browser): 그래픽 화면을 띄우지 않고 백그라운드에서 코드로 제어하며 웹 페이지를 렌더링·테스트·캡처하는 브라우저입니다.

## 5. 백엔드 · API · 데이터베이스 · 데스크톱 및 자동화

### 백엔드 프레임워크 및 API 통신
- **클라이언트-서버 구조**(Client-Server Architecture): 사용자 화면을 담당하는 클라이언트(프론트엔드)와 비즈니스 로직·데이터 처리를 담당하는 서버(백엔드)가 네트워크로 통신하는 구조입니다.
- **FastAPI** / **Uvicorn** / **Pydantic** / **httpx**: 고성능 Python 비동기 웹 프레임워크(FastAPI), ASGI 웹 서버(Uvicorn), 데이터 유효성 검증 라이브러리(Pydantic), 비동기 HTTP 클라이언트(httpx) 조합입니다.
- **기타 백엔드 프레임워크**: Express, NestJS (Node.js), Django, Flask (Python), Spring Boot (Java) 등이 언급됩니다.
- **REST API** / **RESTful API** / **GraphQL**: HTTP 메서드와 URI를 통해 자원을 주고받는 표준 웹 API 설계 방식(REST)과 클라이언트가 필요한 데이터 구조만 선택해 요청하는 쿼리 언어(GraphQL)입니다.
- **HTTP 메서드**(`GET`, `POST`, `HEAD`): 데이터 조회(`GET`), 생성·전송(`POST`), 본문 없이 헤더 정보만 빠르게 수신(`HEAD` - 네이버 서버 시간 조회에 사용)하는 통신 방식입니다.
- **HTTP 상태 코드**(Status Code): 요청 처리 결과를 나타내는 3자리 숫자입니다. (`200 OK`, `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `503 Service Unavailable`, `504 Gateway Timeout`)
- **HTTP 헤더**(Header): 요청·응답의 부가 정보를 담는 영역입니다. (`Date`: 서버 시각, `Authorization`: 인증 토큰, `Content-Type`: 데이터 형식)
- **엔드포인트**(Endpoint) & **페이로드**(Payload): API가 외부 요청을 받아들이는 URL 경로(엔드포인트)와 요청·응답에 실어 보내는 실제 데이터 본문(페이로드)입니다.
- **미들웨어**(Middleware) & **프록시**(Proxy): 요청과 응답 사이에서 인증·CORS·로깅 등을 가로채 처리하는 중간 계층(미들웨어)과, 프론트엔드 개발 서버에서 백엔드 API로 요청을 중계하는 대리 서버(프록시)입니다.
- **CORS**(Cross-Origin Resource Sharing): 브라우저 보안 정책상 서로 다른 출처(도메인·포트) 간 리소스 요청을 허용할지 제어하는 HTTP 헤더 기반 메커니즘입니다.
- **데이터 직렬화 및 인코딩**: **JSON**(키-값 기반 표준 텍스트 데이터 형식), **CSV**(쉼표 구분 표 데이터), **Base64**(바이너리 이미지 등을 텍스트로 변환하는 인코딩), **UTF-8 / cp949**(유니코드 vs 윈도우 한글 콘솔 문자 인코딩).

### 비동기 처리 · 네트워크 · 성능 최적화
- **비동기 처리**(Asynchronous Execution): 작업 완료를 기다리지 않고 다른 작업을 동시에 진행하는 방식입니다. (`async`/`await`, `Promise`, Python `asyncio`)
- **멀티스레딩**(Multithreading) & **데몬 스레드**(Daemon Thread): 하나의 프로세스 안에서 여러 실행 흐름(스레드)을 동시에 돌려 GUI 창이 멈추지 않게 백그라운드 작업을 처리하는 기법입니다. (메인 프로그램 종료 시 함께 종료되는 백그라운드 스레드가 데몬 스레드)
- **콜백**(Callback): 특정 작업이 끝나거나 이벤트가 발생했을 때 호출되도록 넘겨주는 함수입니다.
- **네트워크 왕복 시간**(Ping / RTT) & **타임아웃**(Timeout): 클라이언트가 서버에 요청을 보내고 응답이 돌아오기까지 걸리는 시간(Ping)과, 무한 대기를 막기 위해 설정하는 최대 대기 시간(Timeout)입니다.
- **재시도 및 백오프**(Retry & Backoff) & **캐싱**(Caching): 일시적 네트워크 오류 시 간격을 늘려가며 재시도(`retry-requests`)하고, 최근 응답을 임시 저장(`requests-cache`)해 속도와 안정성을 높이는 기법입니다.

### 데이터베이스 · BaaS · 서버리스
- **SQL** & **RDBMS**(관계형 데이터베이스): 정형화된 테이블과 행·열 구조로 데이터를 저장하고 SQL 질의어로 다루는 데이터베이스입니다. (예: PostgreSQL, SQLite)
- **NoSQL** & **인메모리 키-값 저장소**(In-Memory Key-Value Store): 비정형 데이터를 다루거나 디스크 대신 메모리에 데이터를 올려 초고속 캐시·세션 저장소로 쓰는 DB입니다. (예: Redis)
- **스키마**(Schema) & **ERD**(Entity-Relationship Diagram): 데이터베이스 테이블의 구조·자료형·제약조건 정의(스키마)와 테이블 간 관계를 시각화한 다이어그램(ERD)입니다.
- **마이그레이션**(Migration) & **인덱싱**(Indexing): DB 스키마 변경 이력을 버전 관리해 적용하는 작업(마이그레이션)과 조회 속도를 높이기 위해 색인을 생성하는 작업(인덱싱)입니다.
- **CRUD**: 데이터 처리의 4가지 기본 기능인 생성(Create), 조회(Read), 수정(Update), 삭제(Delete)입니다.
- **ORM**(Object-Relational Mapping) & **JPA**: 객체지향 코드와 관계형 DB 테이블을 자동으로 연결해 주는 기술입니다. (**N+1 문제**: 연관 데이터 조회 시 쿼리가 N번 추가 실행되는 성능 저하 / **EAGER 로딩**: 즉시 로딩 / **트랜잭션**(`@Transactional`): 작업의 원자성 보장 / **동시성 제어**(Locking): 다중 접근 충돌 방지)
- **BaaS**(Backend-as-a-Service) & **Supabase**(수파베이스): 백엔드 서버 구축 없이 DB(PostgreSQL), Auth(회원 인증), Storage(파일 저장소), Realtime(실시간 구독)을 API로 즉시 제공하는 클라우드 플랫폼입니다.
- **서버리스**(Serverless) & **Google Apps Script**(GAS): 개발자가 서버 인프라를 직접 관리하지 않고 코드만 올리면 클라우드에서 실행되는 환경입니다. (GAS는 **V8 런타임** 기반이며, 로컬 개발 도구 **Clasp CLI**, 주기적 자동 실행 기능 **Trigger**를 지원합니다.)

### 데스크톱 앱 · 파이썬 GUI 및 자동화 · 오픈 API
- **Tauri v2**: 웹 프론트엔드(HTML/JS/Next.js)와 **Rust**(`Cargo.toml`) 백엔드를 결합해 가벼운 네이티브 데스크톱 설치 파일(`.exe`, `.msi`)을 만드는 프레임워크입니다.
- **IPC**(Inter-Process Communication): Tauri에서 프론트엔드(웹뷰)와 Rust 네이티브 백엔드 사이에 파일 시스템(`plugin-fs`) 접근 등의 명령을 주고받는 프로세스 간 통신 방식입니다.
- `asset://` **프로토콜** & **AppData**: Tauri 앱이 사용자 OS의 전용 앱 데이터 폴더(AppData)에 저장된 로컬 이미지를 보안 정책 범위 내에서 안전하게 불러오는 커스텀 프로토콜입니다.
- **Tkinter** / **PyAutoGUI** / **키보드 후킹**(Keyboard Hooking): Python 기본 GUI 라이브러리(Tkinter), 마우스·키보드 제어 매크로 라이브러리(PyAutoGUI), OS 수준에서 전역 키 입력을 가로채 감지하는 기법(키보드 후킹)입니다. (**Topmost**: 창을 항상 최상단에 고정)
- **오픈 API**(Open API) & **GIS / 지오코딩**(Geocoding): 누구나 활용할 수 있도록 공개된 외부 API(공공 데이터, Open-Meteo, yfinance 등)와, 지역명·주소를 위도·경도 좌표로 변환하고 지도 위에 시각화하는 지리정보 기술(브이월드, Nominatim)입니다.

## 6. 보안 · 인증 · 전자결제 · Git · 클라우드 배포

### 보안 및 인증
- **인증**(Authentication) & **인가**(Authorization): 사용자가 누구인지 신원을 확인하는 절차(인증)와, 인증된 사용자에게 특정 리소스 접근 권한이 있는지 확인하는 절차(인가)입니다.
- **OAuth 2.0** & **소셜 로그인**: 구글, 카카오 등 외부 플랫폼의 인증 체계를 안전하게 위임받아 로그인하는 개방형 표준 프로토콜입니다.
- **JWT**(JSON Web Token): 사용자 인증 정보와 서명을 JSON 객체에 담아 암호화해 주고받는 자기 수용적(Self-contained) 인증 토큰입니다.
- **Basic Auth**: 사용자 ID와 비밀번호(또는 토스 시크릿 키 + `:`)를 Base64로 인코딩해 HTTP `Authorization` 헤더에 실어 보내는 인증 방식입니다.
- **RLS**(Row Level Security, 행 수준 보안): Supabase(PostgreSQL)에서 사용자가 본인의 데이터 행(Row)에만 접근·수정할 수 있도록 데이터베이스 엔진 차원에서 강제하는 보안 정책입니다.
- **CSP**(Content Security Policy) & **X-Frame-Options**: 웹 페이지에서 허용되지 않은 외부 스크립트 실행이나 다른 사이트의 `<iframe>` 삽입(클릭재킹)을 차단하는 브라우저 보안 헤더입니다.
- **SQL 인젝션**(SQL Injection) & **XSS**(Cross-Site Scripting): 입력창에 악의적인 SQL 쿼리나 자바스크립트 코드를 삽입해 DB를 탈취하거나 사용자 브라우저를 공격하는 대표적인 웹 취약점입니다.
- **AES-256-GCM** & **종단간 암호화**(End-to-End Encryption): 데이터를 저장하기 전에 백엔드 등에서 256비트 대칭키 알고리즘(인증된 암호화 모드 GCM)으로 암호화하여 DB 관리자조차 원문을 볼 수 없게 보호하는 기법입니다.
- **환경 변수**(`.env`, `.env.example`) & **자격 증명**(Credentials): API 키, DB 비밀번호 등 민감한 시크릿을 코드에서 분리해 보관하는 파일과 그 접속 정보입니다.
- **클라이언트 키 vs 시크릿 키**: 브라우저에 노출되어 SDK 초기화에 쓰이는 공개 키(Client Key)와, 절대 외부에 노출되면 안 되며 백엔드 서버에서만 사용하는 비밀 키(Secret Key)의 구분입니다.

### 전자결제 (Toss Payments 연동)
- **PG / 결제 SDK**(Payment Gateway): 온라인 결제를 중개하는 서비스(토스페이먼츠)와 프론트엔드 결제 위젯 연동을 돕는 소프트웨어 개발 키트입니다.
- **서버 신뢰 모델**(Server-Authoritative Model): 클라이언트(브라우저)는 결제 인증만 담당하고, 실제 결제 승인 요청과 유료 권한 부여는 반드시 신뢰할 수 있는 백엔드 서버에서 처리해야 하는 보안 원칙입니다.
- **금액 위변조 검증**(Amount Verification): 사용자가 브라우저에서 결제 금액을 임의로 조작해 인증하는 것을 막기 위해, 결제 승인 전 서버 DB에 사전 등록된 주문 금액과 대조하는 필수 검증 과정입니다.
- **빌링키**(Billing Key): 카드 정보를 등록해 발급받는 고유 키로, 매달 사용자의 개입 없이 정기 자동 결제를 청구할 때 사용합니다.
- **페이월**(Paywall) & **라우트 가드**(Route Guard): 유료 결제 사용자에게만 특정 콘텐츠나 페이지 접근을 허용하고 미결제 시 결제 화면으로 유도하는 접근 제어 패턴입니다.
- **웹훅**(Webhook): 가상계좌 입금 완료, 결제 상태 변경 등 외부 서버에서 발생한 이벤트를 내 백엔드 API URL로 실시간 푸시 알림해 주는 역방향 HTTP 콜백입니다.

### Git 버전 관리 및 협업
- **Git** & **GitHub**: 소스 코드의 변경 이력을 로컬에서 관리하는 분산 버전 관리 시스템(Git)과 이를 클라우드에 호스팅해 협업하는 플랫폼(GitHub)입니다.
- **주요 Git 개념 및 명령어**:
  - `init` (저장소 초기화), `status` (상태 확인), `add` (스테이징 영역에 담기), `commit` (세이브포인트 기록), `log` (이력 조회)
  - `remote` (원격 저장소 연결), `push` (클라우드 업로드), `pull` (원격 변경사항 내려받기)
  - `branch` / `checkout` / `merge` (독립 작업 분기 생성·전환·병합), `worktree` (하나의 저장소에서 여러 브랜치를 별도 폴더로 동시 체크아웃)
  - `restore` / `reset` (작업 내용을 이전 커밋 시점으로 안전하게 롤백·복구), `diff --stat` (변경된 파일과 추가/삭제 라인 수 통계 확인)
  - `Fork` & **Pull Request**(PR): 타인의 저장소를 복제해 수정한 뒤 원본 저장소에 병합을 요청하는 협업 흐름
  - `.gitignore`: `.env`, `node_modules/`, `.venv/` 등 Git 추적에서 제외할 파일·폴더 목록을 지정하는 설정 파일
  - **커밋 컨벤션**(Commit Convention): `feat:`, `fix:`, `docs:`, `style:`, `refactor:`, `test:`, `chore:` 등 변경 목적을 표준화된 접두사로 명시하는 규칙

### 클라우드 인프라 · 배포 · 운영 모니터링
- **CI/CD**(Continuous Integration / Continuous Deployment): 코드 변경(`git push`) 시 자동으로 빌드·테스트·배포가 이루어지는 자동화 파이프라인입니다.
- **무중단 배포**(Zero-downtime Deploy), **프리뷰 환경**(Preview Environment), **롤백**(Rollback): 서비스 중단 없이 새 버전을 반영(무중단 배포)하고, PR마다 임시 테스트 URL을 띄우며(프리뷰), 문제 시 클릭 한 번으로 이전 버전으로 되돌리는(롤백) 배포 기능입니다.
- **PaaS**(Platform as a Service) & **SaaS**(Software as a Service): 서버 구축 없이 코드만 올리면 실행·확장해 주는 클라우드 플랫폼(Render, Vercel, Heroku)과, 웹으로 구독해 쓰는 완성형 소프트웨어 서비스(SaaS)입니다.
- **클라우드 호스팅 플랫폼**: Vercel, Render, Cloudflare Pages, Cloudflare Workers, GitHub Pages, AWS, GCP.
- **네트워크 및 전송**: **CDN**(전 세계 에지 서버에 정적 파일 캐싱), **에지 캐싱**(Edge Caching), **SSL/TLS**(HTTPS 암호화 인증서), **커스텀 도메인**(Custom Domain), **사설 네트워크**(Private Network).
- **IaC**(Infrastructure as Code): `render.yaml`(Blueprints)이나 Terraform처럼 서버·DB·네트워크 구성을 코드 파일로 정의해 자동 프로비저닝하는 방식입니다.
- **Docker**(도커): 애플리케이션과 실행 환경을 컨테이너 이미지로 패키징해 어디서나 동일하게 실행하는 가상화 기술입니다.
- **크론잡**(Cron Job) & **백그라운드 워커**(Background Worker): 정해진 주기마다 반복 작업을 실행하는 스케줄러(크론잡)와, 큐에 쌓인 비동기 작업을 뒤에서 처리하는 전용 인스턴스(워커)입니다.
- **자동 스케일링**(Auto Scaling), **콜드 스타트**(Cold Start), **자동 휴면**(Spin-down on idle), **헬스 체크**(Health Check): 트래픽에 따라 서버 자원을 자동 조절하고, 유휴 시 서버를 잠재웠다가(Spin-down) 첫 요청 시 깨어나며 지연이 발생하는 현상(Cold Start), 그리고 서버 생존 여부를 주기적으로 확인하는 기능(Health Check)입니다.
- **로깅**(Logging) & **로그 수준**(Log Level): 시스템 동작과 오류를 기록하는 로그(`DEBUG`, `INFO`, `WARN`, `ERROR`)와, 대량 출력을 파일로 격리 저장해 컨텍스트 낭비를 막는 **출력 리다이렉션**(`> test.log 2>&1`) 기법입니다.
- **운영 및 분석 도구**: **GA4**(Google Analytics 4, 사용자 행동 트래킹), **KDS**(Kitchen Display System, 매장 실시간 주문 접수 화면).
- **기본 개발 환경 용어**: **터미널 / CLI**(명령줄 인터페이스), **TUI**(텍스트 기반 터미널 UI), **GUI**(그래픽 사용자 인터페이스), **IDE**(통합 개발 환경), **정규표현식**(RegExp, 패턴 매칭 시 탐욕적 Greedy vs 비탐욕적 Non-greedy 매칭).
