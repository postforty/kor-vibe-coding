# 🧪 [실습] 간헐적 로그인 버튼 먹통 버그 디버깅 랩

이 프로젝트는 **3일차 프롬프트 엔지니어링 실무 전략(CoT와 안전장치)**을 학습자가 직접 눈으로 체감하고, AI 에이전트와 함께 디버깅 실습을 진행해볼 수 있도록 제작된 미니 프로젝트입니다.

---

## 🎯 1. 실습 목표

1. 실제 프런트엔드 실무에서 매우 빈번하게 발생하는 **간헐적 클릭 무반응 버그**를 직접 눈으로 확인합니다.
2. AI에게 그냥 `"고쳐줘"`라고 했을 때와, **"[원인 분석 ➔ 부작용 검토 ➔ 해결 코드]"**라는 체계적 CoT 지시를 내렸을 때의 답변 품질 차이를 체감합니다.

---

## 🚀 2. 실행 방법

별도의 설치 과정(`npm install` 등)이 전혀 필요 없습니다!

1. 파일 탐색기에서 `index.html` 파일을 더블 클릭하여 크롬이나 엣지 등 웹 브라우저로 엽니다.
2. 화면 중앙에 로그인 폼이 나타나고, 화면 하단에 **[실시간 상태 모니터]** 패널이 표시됩니다.

---

## 🔍 3. 버그 재현 방법

1. [로그인] 버튼을 몇 차례 클릭해 보세요.
2. 가상 API 서버가 약 40% 확률로 에러(504 Gateway Timeout)를 발생시키도록 시뮬레이션되어 있습니다.
3. **버그 발생 순간:**
   * 빨간색 에러 로그가 뜨는 순간, 하단 모니터의 `isSubmitting` 값이 `true`로 영구히 굳어버립니다.
   * 이후부터는 입력창 값을 바꾸고 로그인 버튼을 100번 눌러도 **아무런 반응이 없는 먹통 상태**가 됩니다!

---

## 🤖 4. AI 에이전트 비교 실습 (핵심 실습)

Antigravity, Cursor, ChatGPT, Claude 등의 AI 에이전트에게 아래 2가지 방식으로 각각 질문해 보고 결과를 비교해 보세요.

### 🧪 실습 A: 아무 생각 없이 그냥 요청하기 (Before)
```text
ch03/login-bug-demo/script.js 파일인데, 로그인 버튼이 가끔 안 눌려. 고쳐줘.
```
> **관찰 포인트:** AI가 원인이 무엇인지 명확히 짚어주지 않거나, 기존의 유효성 검사 및 디버그 로직을 멋대로 지워버리고 엉뚱한 땜질식 코드를 제시하는 현상을 확인합니다.

---

### 🧪 실습 B: 한 줄 안전장치 CoT 지시하기 (After)
```text
ch03/login-bug-demo/script.js 파일에서 로그인 버튼이 간헐적으로 안 눌리는 버그가 있어.
코드부터 짜지 말고, [원인 분석 ➔ 부작용 검토 ➔ 해결 코드] 순서로 분석해줘.
```
> **관찰 포인트:** 
> 1. **원인 분석:** `try-catch`에서 에러 발생 시 `isSubmitting = false` 및 버튼 활성화 처리가 누락되었음을 정확히 지적하는지 확인합니다.
> 2. **부작용 검토:** 단순히 에러 블록에 코드를 넣는 것을 넘어, `finally` 블록을 써야 하는 이유나 중복 클릭 방지 유지 필요성을 검토하는지 확인합니다.
> 3. **해결 코드:** 기존 코드를 망가뜨리지 않고 가장 안전하게 수정된 코드를 제시하는지 확인합니다.
