## 2. 주요 차이점 및 기술적 배경 분석

### ① CLI & 2.0 Desktop App
* 부모 에이전트가 `invoke_subagent` 도구를 직접 호출하여 백그라운드 서브에이전트를 생성 및 분기 실행합니다.
* `/agents` 패널을 통해 서브에이전트 ID, 실행 상태(`running`, `done`, `killed`), 도구 호출 단계를 실시간 모니터링하고 개별 제어할 수 있습니다.

### ② Antigravity IDE 환경
* IDE 런타임 인터페이스에는 `invoke_subagent` 도구가 직접 주입되지 않으며, **단일 협업 메인 에이전트**가 파일 편집, 터미널 실행, 브라우저 제어 도구를 직접 조율하도록 설계되었습니다.

### ③ `run_command`로 `agy`를 서브에이전트처럼 실행할 때의 한계
* **대화형 TUI 제약**: `agy`는 기본적으로 사용자와 실시간 상호작용하는 대화형 TUI(Terminal UI) 프로그램입니다. `run_command`로 실행 시 백그라운드 태스크로 전환되어 실시간 화면 렌더링이나 단축키 조작이 어렵고, `manage_task(send_input)` 방식으로만 텍스트를 전달해야 하므로 조작이 매우 비효율적입니다.
* **결론**: IDE 환경에서는 셸을 통한 서브에이전트 강제 실행 대신, **컨텍스트 윈도우 오염(Context Bloat)을 원천 차단하는 IDE 전용 대체 워크플로우를 활용하는 것이 최선의 전략**입니다.

## 3. Antigravity IDE 전용 무오염(Zero-Bloat) 5대 실전 전략

### 🥇 1. [추천 1위] 별도 세션 분리 + '요약 파일(Artifact)' 멘션 인계
* **개념**: 별도 조사 세션에서 탐색을 마친 뒤, **정제된 요약 마크다운 파일만 메인 세션으로 인계**하는 완벽한 격리 워크플로우입니다.
* **아키텍처 구조**:
  ```
  [ 조사 전용 세션 (New Conversation) ]
    └─ 수십 개 파일 탐색, 로그 확인 (수만 토큰 소비)
    └─ "핵심 결과만 research_summary.md 파일로 저장해줘"
                  │
                  ▼ (대화 전체 ❌, 요약 파일만 인계 ⭕)
  [ 메인 코딩 세션 (Main Session) ]
    └─ 프롬프트: @research_summary.md 내용 기반으로 결제 로직 수정해줘
  ```
* **실행 절차**:
  1. 좌측 상단 `+ New Conversation`을 눌러 조사 전용 세션을 생성합니다.
  2. 대용량 `grep_search`, `view_file` 탐색을 마음껏 진행한 후 최종 결과를 `research_summary.md` 파일(아티팩트)로 저장하도록 지시합니다.
  3. 메인 작업 세션으로 복귀하여 `@research_summary.md` 파일만 멘션하여 작업을 지시합니다.

> [!CAUTION]
> **`@Conversation` 멘션을 피해야 하는 이유**
> `@Conversation`으로 이전 세션 전체를 멘션하면, 해당 세션의 **수십 개 파일 전문과 도구 실행 로그(전체 트랜스크립트)가 메인 세션으로 그대로 유입되어 심각한 컨텍스트 오염과 토큰 낭비**가 발생합니다.
> 따라서 세션 전체를 멘션하지 말고 **반드시 요약된 마크다운 파일(`@파일명.md`)만 멘션**해야 합니다.

### 🥈 2. [추천 2위] 단일 세션 내 아티팩트(Artifacts) 파일 오프로딩 패턴
* **개념**: 새 대화창을 열지 않고 현재 세션 내에서 컨텍스트를 절약하는 방식입니다.
* **방법**: 검색/분석 상세 내용은 아티팩트 마크다운 파일에 분리 기록하게 하고, 대화창 본문에는 3줄 요약만 출력하도록 프롬프팅합니다.
* **프롬프트 예시**:
  > *"바우처 관련 코드를 분석하되, **대화창에는 3줄 요약만 출력하고 모든 상세 분석 내용과 코드 스니펫은 `research_notes.md` 아티팩트로 저장**해줘."*
* **효과**:
  * 상세 내용은 아티팩트 파일에 분리 저장됩니다.
  * 대화창 본문에는 몇 줄의 요약만 남아 컨텍스트 윈도우 소모를 최소화합니다.

---

### 🥉 3. [추천 3위] 정밀 탐색(Grep & Slice) 및 터미널 대량 로그 리다이렉션
* **정밀 탐색**: 전체 파일을 통째로 읽지 않고 `grep_search`로 함수/키워드만 핀포인트 검색하거나, `view_file`의 `StartLine`/`EndLine` 옵션으로 필요한 50~100줄만 슬라이스해서 조회합니다.
* **대량 로그 리다이렉션**:
  * 대규모 빌드/테스트/데이터 처리 출력은 수만 토큰을 순식간에 소모합니다.
  * 출력을 파일로 리다이렉트한 후 에러 요약만 필터링합니다.
  ```powershell
  # 전체 로그는 파일로 격리 저장
  npm test > test_output.log 2>&1

  # 실패한 원인만 필터링하여 확인
  Select-String -Path test_output.log -Pattern "FAIL|Error"
  ```

### 🎯 4. [추천 4위] 슬래시 커맨드 워크플로우 (`/research`) 규격화
* **개념**: 대규모 코드베이스 탐색 시 불필요한 중간 출력을 차단하고 정제된 포맷만 반환하도록 워크플로우를 템플릿화합니다.
* **설정 파일 예시 (`.agents/workflows/research.md`)**:
  ```markdown
  ---
  description: 대규모 코드베이스를 탐색하고 컨텍스트 낭비 없이 핵심만 요약 보고합니다.
  ---

  1. 검색 대상 키워드와 관련된 파일을 `grep_search`, `view_file`로 탐색합니다.
  2. 코드를 절대 수정하지 마십시오.
  3. 탐색 중 얻은 장문의 로그나 파일 전문을 대화창에 그대로 나열하지 마십시오.
  4. 최종 결과는 아래 형식으로만 간결하게 출력하십시오:
     - **관련 파일 목록** (링크 포함)
     - **핵심 아키텍처 및 데이터 흐름 요약** (3~5줄)
     - **주의사항 및 결론**
  ```
* **사용법**: 채팅창에 `/research [키워드]` 입력 시 규격화된 경량 요약만 반환됩니다.

---

### ⚡ 5. [추천 5위] 국소 수정 시 `Ctrl + I` (Inline Edit) 활용
* **개념**: 사이드바 채팅 컨텍스트를 0% 소모하는 초경량 코드 수정 방식입니다.
* **방법**: 단일 함수 수정, 리팩토링, 주석 추가 등 파일 전체 맥락이 불필요한 작업 시 에디터 영역 블록 지정 후 `Ctrl + I` (macOS: `Cmd + I`)로 즉시 수정합니다.
* **효과**: 사이드바 세션의 대화 컨텍스트를 전혀 쓰지 않아 메인 작업 세션의 컨텍스트가 100% 보존됩니다.

## 4. (심화) 헤드리스 서브에이전트 오케스트레이션 (Python SDK)

IDE 외부에서 독립 에이전트를 프로그래밍 방식으로 조율해야 하는 대규모 배치 작업이 필요한 경우:
* **Antigravity Python SDK (`antigravity-sdk-python`)**를 사용하여 격리된 파이썬 스크립트에서 에이전트를 백그라운드로 실행합니다.
* 크롤링, 대규모 리팩토링 검토 등 무거운 작업을 백그라운드 프로세스에서 완료한 뒤, **최종 결과 JSON/마크다운 요약 파일만 IDE 세션으로 전달**받아 활용할 수 있습니다.
