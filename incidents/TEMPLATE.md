> **한 줄 요약**: (예: 코딩 가이드라인 스킬이 주어졌음에도 대형 파일에서 광역 정규식을 사용해 1,870줄 코드 유실 발생)

## 📌 1. 사건 개요 (Incident Summary)
- **일시 / 작업 환경**: (예: 프론트엔드 리팩터링 작업 중)
- **대상 파일**: (예: `index.tsx` 약 2,200라인 규모 대형 파일)
- **피해 규모**: (예: `2,216 -> 343 lines (-1,873)` 비정상적 라인 유실)
- **발생 증상**: (예: 특정 분기문 수정 중 함수 닫는 괄호 탐욕 매칭으로 중간 코드 전체 삭제)

## ⚠️ 2. 사전 지침 존재 여부 (Pre-existing Guidelines)
> *사고 발생 전 에이전트에게 어떤 지침/스킬/룰이 제공되었는가?*

- **적용된 스킬/룰**: (예: `coding-guidelines/SKILL.md`)
- **명시되어 있던 원칙**:
  - 원칙 1: 속도보다 주의 (Caution over Speed)
  - 원칙 2: 외과수술적 변경 (Surgical Changes: Touch only what you must)
  - 원칙 3: 목표 기반 실행 및 검증 루프 (Verification Loop)
- **에이전트 인지 상태**: 스킬 내용을 읽고 분석(`Analyzed SKILL.md`)했음에도 실행 단계에서 무력화됨.

---

## 🔍 3. 근본 원인 분석 (Root Cause Analysis - 5 Whys)
> *가이드라인이 있었음에도 왜 실패했는가?*

1. **지침 인지와 실행의 괴리 (Speed Bias)**:
   - 한 번의 스크립트 실행으로 여러 곳을 빠르게 끝내려는 조급함 때문에 안전한 절차 우회.
2. **도구 선택의 치명적 오류 (Anti-pattern)**:
   - 2,000줄 이상의 대형 파일에서 괄호/키워드가 중첩되어 있음에도 광역 정규식(`[\s\S]*?`) 사용.
3. **자가 검증(Verification) 루프 생략**:
   - 스크립트 종료 코드(Exit 0)만 믿고 `git diff --stat`을 통한 변경 볼륨(+/- 라인 수) 검증 누락.
4. **인간 검증(Human-in-the-loop) 전 무방비 노출**:
   - 에이전트가 자체적으로 오류를 감지하지 못하고 사용자에게 직접 발견되도록 방치됨.

---

## 🛡️ 4. 재발 방지를 위한 다층 방어 체계 (Defense in Depth)

### ① 에이전트 행동 규칙(Action Items) 강화
- [ ] 정규식 치환 전면 금지 및 100% 완전 일치 문자열(`exact-string match`, `edit_file`) 강제
- [ ] 파일 수정 직후 `git diff --stat` 실행 의무화

### ② 시스템 및 룰(AGENTS.md / Customization) 반영
```markdown
# [반영할 룰 내용]
- 대형 파일 수정 시 정규표현식 일괄 치환 스크립트 사용을 엄격히 금지한다.
- 수정 작업 직후 반드시 `git diff --stat`으로 변경 라인 수를 자가 검증한다.
```

### ③ 개발자(인간)의 통제선 (Human-in-the-Loop)
- 파일 수정 전 `git status`, `git commit`으로 롤백 포인트 확보.
- 에이전트의 "작업 완료" 보고 전 변경 통계(Diff Stat) 확인 요청.
